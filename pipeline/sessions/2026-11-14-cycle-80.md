**Root cause (for a human to fix)**: queue regeneration (Phase 0's "regenerate from
docs/TOPICS.md" step) blindly appends the full rotation as UNWORKED whenever the
previous pass empties out, without checking whether a same-day research digest
already exists for a topic. On a day where the pipeline fires many times (cycles
69-79 all same calendar day), this reliably produces 1-2 topics per regen that are
pure duplicates. This is the same shape as the `infra_queue_same_day_rework` memory
note — recommend making queue regen check `research/<today>-<slug>*.md` before
re-adding a topic as UNWORKED, or re-marking it DONE immediately with a dedup note
instead of letting a cycle spin on it.
