# Common Board: An Open Blackboard Protocol Spec for Cross-Framework Multi-Agent Shared State

Every multi-agent stack eventually needs a place where agents can leave notes for each other — a shared scratchpad that survives beyond a single request/response. The two protocols that got the closest to becoming cross-vendor standards for agents, MCP and A2A, both quietly skip this problem. MCP handles agent-to-tool calls; A2A handles agent-to-agent messaging. Neither one defines what happens when three agents need to read and write the same piece of state without stepping on each other. So every team builds that part themselves, from scratch, with a database and some ad hoc locking logic — the one piece of agent infrastructure that still has no shared vocabulary.

## The Gap

This isn't a hunch — it's the same observation landing from three unrelated corners of the infra world at once. Sentra's "MCP vs A2A" comparison piece states plainly that neither protocol defines shared memory and that no standard agent-memory protocol has foundation backing yet. Cockroach Labs makes the identical point from the database side: "the coordination point is the database, not the task message, and that's exactly what the protocol leaves undefined." And a Blck Alpaca knowledge-base article describes teams manually implementing the classic "blackboard pattern" as a workaround, recommending a hybrid of shared state plus messaging with single-threaded writes to avoid races.

Three independent vendors, three different angles, one converging diagnosis: the blackboard pattern — a shared-state layer multiple agents read and write to coordinate — keeps getting reinvented because nothing standardizes it. A GitHub search for existing attempts turns up only fragmented point implementations: whiteducksoftware/flock (126 stars, actively maintained, pushed as recently as November 3) is the most mature entry, trailed by much smaller efforts like arvarik/bmas (4 stars) and several 0-star student projects. Each is its own framework-specific convention. None of them is a cross-ecosystem spec, and as of now no standards body has stepped in to define one either.

## The Project

The idea is to build the missing layer as an actual protocol, not another one-off implementation: a small, versioned blackboard spec — typed key/record read and write, subscribe-on-change, and single-threaded-write locking per key — plus a reference server that any team can point their agents at. Crucially, the reference server would be exposed two ways: as a plain HTTP/gRPC API, and as an MCP server, so that any agent that already carries an MCP client gets blackboard coordination for free, with no bespoke integration beyond a standard MCP connection.

The goal is for this spec to play the same role for agent coordination that OpenAPI plays for REST, or a shared schema registry plays for event buses — a small contract that LangGraph, CrewAI, AutoGen, or a raw function-calling loop can all target without needing to agree on anything else. The concrete pieces: a minimal spec document covering schema, locking semantics, and the subscription model; a SQLite-backed reference server to start; the MCP wrapper exposing that server as MCP resources and tools; thin client adapters for LangGraph and a raw function-calling loop to actually prove cross-framework interop rather than just claim it; and a migration note for teams currently sitting on a hand-rolled Postgres or Redis table, so there's a real on-ramp away from the DIY version.

## Why Now

MCP became a de facto cross-vendor standard through 2026, with tooling from both the OpenAI and Anthropic ecosystems adopting it. That gives a project like this something the earlier, pre-MCP attempts at the blackboard pattern never had: an already-mature, already-trusted transport and auth layer to build a shared-state spec on top of, instead of having to invent a transport layer from scratch just to get the coordination layer off the ground.

Worth being honest about the risk profile here too. Protocol-adoption projects live or die on backing, and a small team's spec risks becoming exactly the kind of "one more incompatible point-implementation" the digest's own sources are complaining about — the irony isn't lost on anyone building this. MCP's resource and subscription model may also not cleanly support the single-threaded-write guarantees this needs without an extension, which isn't fully this project's call to make. And A2A's own steering effort could ship an official shared-memory extension first, which would make this moot — the source material explicitly flags that timeline as unknown. Finally, for most single-team, single-framework deployments, a hand-rolled Postgres or Redis table is already good enough; the value here is concentrated specifically in the cross-vendor, cross-framework case, not the general one.

## Tangible Impact

**Population**: Engineering teams building cross-vendor, cross-framework multi-agent systems that use both MCP (for tool access) and A2A or an equivalent agent-to-agent protocol in the same deployment — the exact overlap Sentra's comparison piece addresses — who today each independently reinvent a Postgres- or Redis-backed shared-state table specifically because neither spec defines one for them.
**Mechanism**: Instead of every team designing and maintaining its own bespoke shared-state schema and locking logic from scratch, a new agent joining a blackboard-coordinated pipeline gets coordination state for free through its existing MCP connection — turning a multi-day custom-schema-and-glue-code task into a standard integration.
**Measure**: (1) integration time for a new agent to join an existing blackboard-coordinated pipeline (target: under an hour via the reference MCP server, versus the multi-day hand-rolled builds the digest's sources describe); (2) number of independently-built frameworks (LangGraph, CrewAI, a raw function-calling loop) demonstrated coordinating through one shared blackboard instance in a reference demo; (3) adoption proxy — stars/forks/downstream integrations of the reference server versus the fragmented point-implementations it targets replacing (whiteducksoftware/flock's 126 stars as the bar to clear).
