# Boundary Diff: Catching Silent Context Loss at Agent-to-Agent Handoffs

A multi-agent pipeline can run clean from start to finish — no crash, no exception, no alert — and still quietly hand a downstream agent half the context it was supposed to get. Picture a research agent emitting a 14,000-token packet of findings, and the planner that consumes it next actually receiving 8,000 tokens because something in between truncated it. Nothing broke in the sense any monitor checks for. The pipeline looks healthy. It just forgot things. Days later someone notices the final output is missing a constraint an earlier agent clearly established, and the only way to find out why is to manually reconstruct what each agent actually saw.

## The Gap

That 14,000-into-8,000 example isn't hypothetical — it's a cited case from a practitioner write-up, part of a pattern showing up across multiple independent sources (fiddler.ai, atlan.com, qawerk.com) of teams saying ordinary logging "doesn't capture why an agent handed off, what context was dropped at the boundary, or whether guardrail state transferred." The fix people are reaching for is DIY: carry a correlation ID on every call, stitch together a custom trace, hand-roll the comparison. That's the tell. When three separate write-ups independently arrive at the same workaround instead of pointing to a tool that already does it, the capability doesn't exist yet as something you install.

It's not that the observability space is empty — it's the opposite problem. LangSmith, Langfuse, and Arize Phoenix already do mature, maintained cross-agent tracing, and OpenTelemetry's GenAI semantic conventions now define standard `invoke_agent`/handoff spans that major frameworks emit by default. But a 2026 dev.to evaluation that went through "every AI agent observability tool on the market" landed on the same verdict: all of them show *that* a handoff happened, none show *what content was lost* at it. The gap is narrow and specific — it's a DIY hole inside an otherwise well-covered market, not a greenfield problem. Worth naming honestly: any of those vendors could ship this as a feature fast, since they already capture the payload content it needs. The reason this is worth building anyway is that nobody has, yet, and the substrate to do it cheaply only matured this year.

## The Project

The idea is a diffing layer, not another tracer. It wraps each framework's handoff point, captures the exact payload the sending agent emitted and the exact payload the receiving agent actually got, and diffs the two: byte/token-count delta, field-level drops for structured payloads, and a classifier distinguishing a deliberate transformation (summarization, redaction, reformatting) from an accidental one. Cross a threshold — say, 15%+ content loss with no corresponding summarization tag — and the handoff gets flagged with a report that names precisely what went missing, tied back to the run and trace it happened in.

The reason this is newly buildable rather than a years-old obvious idea: OTel GenAI conventions only matured in 2026, and it's only this year that LangGraph, CrewAI, and AutoGen/AG2 started emitting handoff spans carrying the actual payload content, not just metadata about the call. A year ago, a tool like this would have needed bespoke per-framework instrumentation just to get at the content. Now the raw substrate already exists — which is also exactly why the gap is still open: the instrumentation got there first, and nobody's built the diff engine on top of it yet.

It also complements rather than duplicates another idea already in this pipeline — a correlation-ID-and-heartbeat tracer that answers "which handoff broke a crashing run." That tool localizes failure. This one answers a different question: what content silently vanished on a run that never crashed at all. The two could eventually share an instrumentation layer, but the failure signal each is built to catch is genuinely distinct.

## Tangible Impact

**Population**: Engineering teams operating production multi-agent pipelines on LangGraph, CrewAI, or AutoGen/AG2 that pass large context packets between agents (research-synthesis chains, document-processing pipelines, support-triage handoffs) — the same population already using Langfuse/LangSmith/Arize Phoenix for general tracing, per those products' own multi-agent docs, but left without visibility into this specific failure class.

**Mechanism**: Today, silent truncation or field loss at a handoff produces no alert — it only becomes visible when a downstream agent's output quality degrades and an engineer manually reconstructs what each agent actually saw. Automated payload diffing surfaces the loss at the moment it happens, with the specific content and the specific boundary named, replacing a reactive quality investigation with a proactive flag.

**Measure**: (1) percentage of handoffs with unflagged, unintentional content loss above a declared threshold, detected automatically vs. previously invisible, on a pilot team's pipeline; (2) time from a downstream quality complaint to identified root-cause boundary, before vs. after; (3) reduction in "missing context" hallucination incidents traceable to an upstream truncation, measured on a held-out incident log.

## Try It

The one-shot half of this idea is already a Claude Code skill: [`skills/multiagent-handoff-context-diff-tool/`](../skills/multiagent-handoff-context-diff-tool/). Straight from its `SKILL.md`:

> Diffs the exact payload one AI agent emitted against the exact payload the next agent actually received at a single suspect handoff, flagging silent truncation, dropped fields, or transformations distinct from declared summarization. Use when a multi-agent pipeline (LangGraph, CrewAI, AutoGen/AG2, or similar) produced a downstream quality problem and you suspect content was lost between two specific agents, but nothing crashed or errored.

You don't need any instrumentation installed to use this version — just the two payloads from one handoff you already suspect went wrong. Paste `skills/multiagent-handoff-context-diff-tool/README.md` into any AI chat tool (Claude, ChatGPT, Gemini, Copilot Chat) along with the sender's actual output and the receiver's actual input, or drop the whole `skills/multiagent-handoff-context-diff-tool/` folder into `~/.claude/skills/` if you're running Claude Code. This is a one-time diff of a single handoff, not a continuous monitor — if you're working a long multi-hop chain and don't yet know *which* handoff is the culprit, localize that first by other means, then come back with the two specific payloads at that boundary.

The full continuous-capture version — wrapping every live handoff automatically instead of diffing one pasted pair by hand — is still the open MVP: wrap one framework's handoff points (LangGraph first), build the diff engine, and validate it by injecting a known truncation limit on one edge and confirming the tool flags exactly that edge with the correct loss description. That's a 2–3 week build for 1–2 people. Two things worth knowing before investing further: storing full payload content at every handoff for diffing carries a real storage/privacy cost at scale and needs a sampling or redaction strategy from day one, and reliably telling "unintentional loss" apart from "deliberate summarization" — without flagging every legitimate compression step as a bug — is the hardest unsolved part of the design, harder than the diffing mechanics themselves.
