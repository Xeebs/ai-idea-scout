# LangPack: Context Packs That Make AI Coding Assistants Fluent in Low-Resource Programming Languages

Ask an AI coding assistant for help in Python and it feels like magic. Ask it for help in COBOL, Pharo, Fortran, or your company's homegrown DSL, and the magic quietly evaporates — it starts inventing list comprehensions that don't exist, guessing at a standard-library function that was never written, and defaulting to naming conventions borrowed from whatever language it saw ten million more times in training. Nobody tells you this is happening. You just notice the suggestions are worse, and you have no lever to pull.

## The Gap

OpenAI said it plainly in a blog post that made the front page of Hacker News (110 points, 104 comments): mainstream AI coding tools are strong on high-resource languages and meaningfully weaker on niche, legacy, or regional ones with little training data — think COBOL, Fortran, Pharo, internal DSLs, or regional dialects of mainstream languages. OpenAI's own framing calls this an open research problem, not a solved one. A second, smaller thread on Hacker News shows the human cost from the other direction: "Ask HN: As developers from low-income countries, how to cope with AI replacement?" — developers worried about being displaced by tools that were never built with their stack or their market in mind.

The same 30-day window produced four separate academic efforts to measure this exact gap — CangjieBench (for the Cangjie language), BigCodeBench-MultiPL (extending into Julia, Fortran, R), OpenAI's own MultiLangBench, and a dedicated Pharo code-completion benchmark. That's the tell: everyone's busy proving the gap exists and sizing it, and nobody has shipped the thing that actually closes it for a working developer today. One of the cited papers notes that even GitHub Copilot still doesn't support truly no-resource languages. The gap-analyst's verdict on this pattern was PARTIAL, not OPEN, specifically because of that benchmarking activity — but a benchmark is not a tool, and none of these four efforts are evaluation-adjacent production software a team can install this afternoon.

## The Project

The fix doesn't require retraining a model or waiting for better multilingual coverage — fine-tuning per niche language isn't something a small team can do anyway. Instead: a tool that generates and maintains a "context pack" for a specific low-resource language or codebase dialect. Feed it a language's reference docs, style guide, and a representative sample of real code — pulled straight from a GitHub repo, or pasted by hand for codebases that can't be — and it produces a structured pack: a condensed language reference card, a catalogue of idioms and patterns specific to that language or codebase, a named list of the AI assistant's actual failure modes for that language (e.g., "frequently hallucinates a Python-style list comprehension that doesn't exist here"), and the local test-harness convention. That pack loads straight into a coding assistant's context — a Claude Code skill, a section of CLAUDE.md/AGENTS.md, or a system-prompt injection for any other tool — to measurably lift suggestion quality without touching the underlying model.

The real leverage is in the second half of the idea: a shared, versioned registry of these packs, so the next team working in Pharo, COBOL, or a regional DSL starts from a maintained asset instead of rediscovering the same assistant failure modes from scratch, alone, for the hundredth time.

## Tangible Impact

**Population**: Developers maintaining production systems in low-resource programming languages — concretely, this spans two overlapping groups: (1) maintainers of legacy mainframe/enterprise languages (COBOL alone reportedly still runs an estimated $3 trillion/day in transactions through legacy systems, with a documented, aging, shrinking developer workforce per multiple 2025-2026 industry reports) and (2) developers in low-income countries working in regional or niche stacks where training-data scarcity compounds existing unequal access to AI tooling, the exact anxiety raised in the digest's Ask HN thread.
**Mechanism**: Today a developer in a low-resource language gets noticeably worse AI coding assistance with no way to improve it short of writing extensive in-context examples by hand, every session, from memory. A generated, reusable context pack front-loads that corrective context once, in a form that persists across sessions and across a whole team, converting an individual's repeated manual workaround into a shared, improvable asset.
**Measure**: (1) suggestion-acceptance rate and bug-introduction rate on a held-out set of real tasks in the target language, with vs. without the pack loaded, benchmarked against one of the existing low-resource-language benchmarks (CangjieBench, BigCodeBench-MultiPL, Pharo benchmark) for an apples-to-apples score; (2) time-to-onboard a new team member onto a legacy-language codebase, self-reported before/after; (3) number of maintained, versioned packs covering distinct languages/dialects in the shared registry over time.

## Try It

A companion Claude Code skill, [`skills/low-resource-language-coding-context-pack/`](../skills/low-resource-language-coding-context-pack/), is already written: *"Generates a reusable 'context pack' (idiom catalogue, known AI-assistant failure modes, reference card, test-harness pattern) for a low-resource or niche programming language/dialect, to drop into a CLAUDE.md or project skill so coding assistants stop defaulting to mainstream-language habits."*

Point it at a GitHub repo (its preferred, connected path) or paste in 5-15 real code files plus a style guide if the codebase can't be pulled via API — common for proprietary legacy systems. It ingests the corpus, extracts idioms and conventions, probes for the assistant's likely failure modes by contrasting generic suggestions against what the real code actually does, and hands back one markdown pack ready to paste into CLAUDE.md or save as a project skill. To use it: paste the `README.md` into any AI chat tool, or drop the `skills/low-resource-language-coding-context-pack/` folder into `~/.claude/skills/` if you're on Claude Code.

## Risks & Open Questions

There's a real chance context-pack injection alone can't close the gap these benchmarks measure if the underlying failure is tokenizer or training-data scarcity rather than missing in-context examples — the MVP's whole point is to run the before/after benchmark experiment and find out rather than assume. Legacy enterprise codebases like COBOL mainframes are often proprietary and can't be pulled via the GitHub API at all, meaning the two populations named above may need genuinely different ingestion paths — open regional/niche languages via the connector, proprietary legacy systems by manual, on-prem paste — which is worth scoping around rather than papering over. And a shared public pack registry built from real production code raises its own confidentiality questions; the registry should store only the abstracted pack, never the source corpus itself.
