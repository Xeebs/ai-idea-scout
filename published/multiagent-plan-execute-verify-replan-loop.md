# Second Look: An Independent Completeness Verifier for Multi-Agent Plan-Execute Loops

A multi-agent "deep research" pipeline doesn't fail loudly. It ships a confident, well-formatted answer the moment its own orchestrator decides the aggregation step is done — and nobody downstream can tell a thorough answer from a polished one with a hole in it until a human later notices the missing competitor, the uncited claim, or the question nobody actually answered. That's the gap an ICLR 2026 workshop paper just put a number on, and it's a number worth sitting with: adding an explicit verifier between the planner and its workers raised answer completeness from 3.1 to 4.2 and source quality from 2.6 to 4.1 on a 5-point scale, across 25 expert-curated market-research queries. The fix exists in a paper. It doesn't exist as something a team running LangGraph, CrewAI, or the OpenAI Agents SDK can actually install.

## The Gap

The paper's result landed in the same 30-day window as a live practitioner debate about whether it's even possible to self-verify. A "verifier paradox" rebuttal and arkforge.tech's "Agent Blind Spots" post both make the same core argument: an orchestrator's own logs, summaries, and confidence claims are just more claims the system makes about itself. A verifier that reads the orchestrator's self-description of its own work doesn't add independence — it just adds a second opinion from the same witness. Nobody has shipped an *independent* checker that an engineering team could actually adopt into a live pipeline.

It's not that nothing adjacent exists. Megagon Labs' VeriMAP (github.com/megagonlabs/veriMAP) ships real code with per-subtask verification functions — but it checks whether individual subtasks were done correctly, not whether the combined output actually answers the original ask. That's a meaningfully different question. A pipeline can get every subtask technically right and still miss half of what the user wanted to know. The paper itself is still workshop-stage, evaluated on a narrow 25-query benchmark. Put together: real evidence the problem is both solvable and unsolved, converging from three independent directions — an academic benchmark, a practitioner critique, and a field-notes post — in the same month.

## The Project

The fix is a verification layer that sits between a multi-agent pipeline's aggregation step and whatever consumes its output — architecturally separate from the orchestrator, not a function call inside it. Instead of trusting the orchestrator's summary of what its workers found, the verifier re-reads the original query cold and every worker's raw output, and scores the result on three checkable axes: completeness (does every sub-question in the original ask have a traceable answer somewhere in the raw outputs), source quality (are the claims backed by actual retrieved evidence or just confidently asserted), and coverage (what obvious angles never got explored at all). A clean result passes through. A result with gaps triggers a bounded replan — a structured, numbered gap report naming exactly what's missing, not a vague "try again" that burns another full, expensive run.

The independence is the entire point, and it's also the easiest part to get wrong. A verifier is only doing new work if it never sees or inherits the orchestrator's own self-assessment. The moment it reads the orchestrator's synthesized summary instead of the raw per-worker outputs, it has quietly reproduced the exact self-verification failure the "Agent Blind Spots" critique names — a second model agreeing with the first model's account of itself. The project's components reflect that discipline: a query-decomposition extractor that works from the original ask alone, a per-sub-question evidence-grounding checker run directly against worker outputs, a structured gap-report generator a replanning step can actually consume, framework adapters for LangGraph/CrewAI/the OpenAI Agents SDK's run-state objects, and a replay harness to reproduce the paper's own completeness/source-quality scoring against a team's own queries rather than taking the 25-query result on faith.

## Tangible Impact

**Population**: Teams running multi-step, multi-agent research or analysis pipelines whose output feeds a real decision — market research, competitive analysis, due diligence, and internal "deep research" tooling built on LangGraph/CrewAI/AutoGen (a combined 300k+ GitHub stars across those three frameworks is a rough proxy for how many teams are assembling orchestrator-aggregates-worker-output pipelines today with no independent completeness check).

**Mechanism**: Today, an incomplete or source-thin synthesized answer ships the moment the orchestrator's own aggregation step decides it's done — nobody downstream can tell a thorough answer from a confidently-worded gap until a human later notices a missed competitor or an unsupported claim. An independent verifier converts that silent failure into a caught, structured gap report before the answer ships, and a bounded replan closes the specific gap instead of a full, expensive re-run.

**Measure**: (1) Answer completeness and source-quality scores (same 5-point rubric as the paper) on a pilot team's own query set, with-verifier vs. without. (2) Rate of post-delivery human corrections ("this missed X") on verified vs. unverified pipeline runs, before/after adoption. (3) False-positive replan rate — how often the verifier triggers a replan on an output a human judge would have accepted as complete, to confirm the check isn't just adding cost without catching real gaps.

## Try It

A standalone slice of this idea is already built as a Claude Code skill: [`skills/multiagent-plan-execute-verify-replan-loop/`](../skills/multiagent-plan-execute-verify-replan-loop/). Its one-line job, straight from the `SKILL.md`:

> Independently audits a completed multi-agent plan-execute run (original query + planner task breakdown + raw worker outputs) for completeness gaps and unsupported claims, producing a structured gap report and a pass/replan verdict.

This is the one-shot, "I already have a finished run and want a second opinion before I trust it" half of the idea — not the live middleware. To use it: either paste `skills/multiagent-plan-execute-verify-replan-loop/README.md` into any AI chat tool (ChatGPT, Claude, Gemini) along with your original query, the planner's task breakdown, and each worker's raw output, or drop the whole `skills/multiagent-plan-execute-verify-replan-loop/` folder into `~/.claude/skills/` if you're running Claude Code. One thing to get right going in: it needs each worker's *raw* output, not the orchestrator's own aggregated summary — feed it the summary instead and it will flag the input as insufficient rather than fake an audit, because that's exactly the self-verification failure the whole idea exists to avoid.

Worth knowing before you build on this: Megagon's VeriMAP already covers subtask-level verification with real shipped code, and the underlying paper's 3.1→4.2 completeness gain comes from a 25-query academic benchmark that hasn't yet been reproduced on a team-authored query set. If your actual pain point is "did each subtask execute correctly" rather than "did the combined answer cover everything I asked," VeriMAP may already be the better fit.
