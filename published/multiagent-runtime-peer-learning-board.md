# Lesson Board: Mid-Run Peer Learning for Multi-Agent Teams

Put three coding agents on the same fan-out task and watch agent B discover, twenty minutes after agent A already learned it the hard way, that the same API call needs a retry with different parameters. Agent A paid for that lesson in failed calls and wasted tokens. Agent B pays for it again, from scratch, because nothing in most multi-agent setups lets one agent's mid-run correction reach a teammate before the run ends — if it reaches them at all.

## The Gap

The complaint showed up on Hacker News on 2026-11-06 in a low-engagement but precisely on-point submission, "Peer Learning Between Agents in a Multi-Agent Team," describing exactly this: agents on the same live task learning from each other's successes and mistakes mid-run, as something distinct from offline multi-agent reinforcement learning. The repo that submission pointed to, `github.com/Mininglamp-AI/Octo`, turned out not to resolve on GitHub's API — a dead end on its own. But chasing the idea further surfaced two independent, peer-reviewed, code-available academic projects tackling essentially the same problem within the past year: LessonL (NeurIPS 2025, agents pass lessons to each other during collective problem solving) and PEEPLL (TMLR 2025, agents seek help from peers online, mid-run). Three independent threads converging on the same gap inside a month is exactly the kind of recurrence that moved this out of "maybe interesting" and into "worth building": nobody has taken the underlying mechanism from round-based academic benchmarks to something continuous and framework-agnostic that a production multi-agent system could just run.

## The Project

The idea is a shared "lesson board" that a team of agents collaborating on one live task reads from and writes to continuously — not just at the start or end of a run, which is how LessonL and PEEPLL's round-based and query-based designs work today. When an agent's action fails and it then succeeds on a retry, or gets corrected by a human or verifier, the board captures the before/after as a generalized lesson — "when doing X, check Y first" — tagged by task type, and makes it immediately queryable by every other agent still working on related subtasks in that same run. The whole point is timing: a teammate three steps behind doesn't repeat a mistake that was already caught moments earlier in the same run, instead of only in the next training cycle or the next benchmark round.

Under the hood, that means four moving parts: a lesson-write hook that triggers on detected fail-then-succeed patterns in an agent's trace; a lightweight lesson store scoped per run rather than global, specifically to avoid stale lessons from one run contaminating an unrelated one; a pre-action lesson-check an agent consults before acting; and a decay/expiry policy so lessons don't outlive their relevance within a run. None of this is a bolt-on feature — the live, continuous propagation is the entire reason this is worth building over the academic versions that already exist.

## Tangible Impact

**Population**: Teams running multi-agent systems where several agents work the same live task in parallel or in a pipeline — multi-agent coding-task fan-out, multi-step research/data-extraction pipelines, or multi-agent customer-support triage — the exact production shape LessonL and PEEPLL were built to study academically, now at the scale where a repeated mistake across agents on the same run has a measurable cost (wasted tokens, wasted wall-clock time, a second agent hitting the same wall the first one already climbed).
**Mechanism**: Without this, each agent on a shared task learns only from its own trial and error within its own context window — if agent A discovers that a particular API call needs a retry with different parameters, agent B doing a similar call later in the same run has no way to know and repeats the same failed attempt from scratch; a live lesson board turns one agent's hard-won fix into every other agent's free knowledge within the same run, not the next one.
**Measure**: (1) rate of repeated identical/near-identical failures across different agents within one multi-agent run, before vs. after the lesson board is active; (2) total tokens/wall-clock time spent on retries attributable to a mistake another agent had already solved in the same run; (3) task-completion success rate on multi-agent benchmarks (e.g., a multi-step coding or research benchmark run with several agents in parallel) with the board on vs. off.

## Try It

A companion skill, `skills/multiagent-runtime-peer-learning-board/`, handles the one-shot drafting piece underlying the board's write hook — turning one agent's raw fail-then-succeed trace into a broadcast-ready lesson, confidence-scored and stripped of run-specific details. Its one-line description: "Turns one agent's raw fail-then-succeed trace into a generalized, confidence-scored lesson card ready to broadcast to teammate agents (or a human reviewing a multi-agent run), so the same mistake isn't repeated by every agent on the same task separately."

It's useful standalone, before any live board exists — paste the `README.md` into any AI chat tool along with a trace excerpt (the failed attempt and the one that succeeded) to get a lesson card and a one-line broadcast message back. For Claude Code, drop the whole `skills/multiagent-runtime-peer-learning-board/` folder into `~/.claude/skills/` and it activates automatically whenever a multi-agent run hits a fail-then-succeed pattern worth generalizing.

Worth being honest about the risk here: LessonL's and PEEPLL's own authors are the most likely people to beat this to production, since both are active 2025 publications with maintained code — and automatically detecting a genuine, generalizable "fail-then-succeed" pattern (versus noise, or a fix that only worked by coincidence) is itself a judgment call. A bad lesson that actively misleads a teammate is worse than no lesson at all, which is why the skill's own confidence scoring defaults to LOW and says so explicitly whenever the causal story behind a fix isn't clear.
