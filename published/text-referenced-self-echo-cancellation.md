# Hear Myself Not: A Vendor-Agnostic Text-Referenced Self-Echo Filter for Voice Agent STT

Every voice agent has the same embarrassing failure mode: it hears itself talk. Acoustic echo cancellation is supposed to stop a microphone from picking up the agent's own TTS output, but on cheap speakerphones, budget headsets, and robotics hardware, AEC is weak enough that the agent routinely transcribes its own voice as user input — then either loops on itself or falsely triggers a "barge-in" nobody actually spoke. Three weeks ago one STT vendor shipped a real fix. Everyone not using that vendor is still stuck.

## The Gap

On November 3, 2026, Soniox quietly released STT v6 (`stt-rt-v6`/`stt-async-v6`) with a technique that sidesteps the acoustic problem entirely: instead of trying to cancel the agent's voice out of the audio signal, it streams the agent's own outgoing TTS *text* into the STT model itself, so the model can filter its own speech out of the transcript semantically rather than acoustically. Coverage of the release — Soniox's own blog, marktechpost, voiceaispace.com — confirms it shipped. But confirmed-shipped and confirmed-solved aren't the same thing here. The only independent write-up found testing it (a Korean-language piece) ran on synthetic audio only, explicitly noting no real-device testing yet. No second vendor, and no open-source implementation, has reproduced the trick. It's locked inside one proprietary product that's barely two weeks old at the time this gap was scored.

That leaves every team not on Soniox's STT — Whisper-based pipelines, Deepgram, self-hosted models — exactly where they were before: relying on acoustic AEC alone, which is precisely the thing that breaks down on the hardware that needs this fix most. Robotics platforms, kiosk voice interfaces, and call setups running on cheap speakerphones don't get to just swap STT vendors to inherit Soniox's solution; a lot of them are locked into a different stack for cost, self-hosting, or language-coverage reasons that have nothing to do with echo cancellation.

## The Project

The fix is a standalone middleware that sits between any voice agent's TTS output and its STT input — engine-agnostic by design, so it works whether the transcript comes from Whisper, Deepgram, or something self-hosted. It tracks what text the agent is currently speaking, estimates word-level timing from the TTS engine's own phoneme/duration output, and then post-filters the STT transcript by aligning and subtracting the segments that match expected self-speech — both semantically and temporally, not just acoustically. That's the same core insight Soniox proved commercially viable, just generalized into a drop-in layer instead of a proprietary feature, and benchmarked on real recorded hardware instead of synthetic audio only — closing exactly the gap the one independent test flagged and couldn't answer.

Concretely: a Python middleware package hooking into an agent framework's existing TTS-generation and STT-input event streams (LiveKit Agents and Pipecat both already expose these maturely — no new API surface needs to be invented), doing fuzzy text/timing alignment between what the agent expected to say and what the STT engine actually heard, and stripping the matched segments before they reach the agent's reasoning step. No third-party API, no user-pasted data — both signals being fused already live inside the agent's own running pipeline.

## Tangible Impact

**Population**: teams building voice agents on open or non-Soniox STT stacks (Whisper.cpp, Deepgram, local models) deployed on hardware with weak acoustic echo cancellation — robotics/kiosk voice interfaces, cheap speakerphone-based call setups, and full-duplex agents where the agent may be speaking while still listening for barge-in. This specifically targets builders who can't just switch STT vendors to get Soniox's fix.
**Mechanism**: the middleware removes self-transcribed segments that acoustic AEC alone missed, preventing the agent from interpreting its own speech as user input — the failure mode that causes an agent to respond to itself in a loop or falsely register a "barge-in" that was just the agent's own voice bleeding back into the mic.
**Measure**: self-transcription false-positive rate (fraction of self-speech incorrectly transcribed as user speech) on a real-hardware test set, before/after the middleware, specifically on weak-AEC hardware; false barge-in rate attributable to self-echo in a live pilot; latency overhead added per utterance (must stay under ~50ms to not itself become a barge-in problem).

## Try It

No companion Claude Code skill exists for this one yet — this is a pure infrastructure build, not a prompt-driven task, so there's nothing to paste into a chat tool or drop into `~/.claude/skills/`. The MVP sketch calls for a 2-3 week build by one audio-ML engineer: a Python package hooking LiveKit Agents' TTS/STT event streams, validated on a 50-utterance real-hardware test against a cheap USB speakerphone with known weak AEC, comparing self-transcription false-positive rates with AEC-only versus AEC-plus-middleware.

Worth being honest about the risks before anyone builds this. Word-level TTS timing is an estimate, not ground truth, so the alignment window needs real tuning to avoid stripping genuine overlapping user speech. There's also a sharper risk underneath all of it: the only independent test of Soniox's own technique couldn't confirm it works well on real hardware — if it turns out the vendor's claims don't hold up outside synthetic audio, that's a sign worth checking against Soniox's own output before building a generalized version of something that might not generalize well in the first place. And a team that's free to just switch STT vendors gets this capability for nothing by moving to Soniox — this project's value lives specifically in the gap for teams that can't.
