- **What it is**: A memory layer that survives across agent sessions, clients (Claude Code, Cursor, etc.), and projects — typically a local store (SQLite with full-text search, or a folder hierarchy of global/client/project notes) that an agent reads back in at session start instead of the user re-explaining the codebase every time.

### P3: "Sticky context slots" to avoid the compaction trap
- **What it is**: A compaction technique that pins a small set of invariant constraints and already-tried approaches outside the summarization pass, so that aggressive context compaction doesn't erase what the agent already attempted — preventing it from repeating failed approaches.
- **Evidence**: tianpan.co blog post "Compaction Traps: Why Long-Running Agents Forget What They Already Tried" (April 2026, per WebSearch) — names the specific failure mode ("the summary drops what the agent already tried, so it repeats failed approaches") and proposes sticky slots as the fix.
- **Why it looks unbuilt/untested**: Framed by its own author as a single practitioner's writeup/pattern name, not a shipped library or framework; no competing or confirming implementation surfaced in search.
- **Maturity**: PARTIAL
- **Verdict notes**: The exact "sticky slots" branding is one author's blog post, but the underlying technique is independently described under other names in multiple places found via WebSearch — "constraint pinning" (Codex CLI/Claude Code write-up with violation-rate numbers), a per-type retention policy pattern (agentpatterns.ai), and an academic "Structured Context Eviction" paper (HuggingFace 2606.11213) — plus a referenced `pi-smart-compact` package with its own architecture doc on invariant retention. No single widely-adopted library implements it as a named, reusable feature, so the gap for a dedicated productized version is real.

### P4: Per-system empirical testing of whether compaction/offloading actually helps

- **Evidence**: fast.io guide "How to Implement Memory Compaction for Long-Running AI Agents" and a counterpoint practitioner source (via WebSearch "'context rot' agent memory compaction technique production") explicitly contradicting each other on whether compaction is a net win.
- **Why it looks unbuilt/untested**: No standard eval harness for "does this context-engineering change help or hurt this agent" was found — each team is running its own one-off A/B rather than using a shared measurement tool, and the sources openly disagree with each other.
- **Maturity**: PARTIAL
