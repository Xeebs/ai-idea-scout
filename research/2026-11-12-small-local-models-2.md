## Candidate patterns

### P1: Hand-rolled small-model-router → cloud-model cascades for agent cost control, with no packaged error-handling layer
- **What it is**: Developers put a cheap local/small model in front of an expensive cloud model as a classifier or first-pass handler, escalating only the harder fraction of requests to the frontier model, to cut agent API spend.
- **Evidence**: dev.to write-up claiming a Gemma-4 local router cut Codex/Claude Code token costs up to 99% (best case); Tom Tunguz's post describing a small router model on a single Mac handling roughly 4/5 of background tasks; an aiweekly.co alert "Dev slashes agent AI costs 75% with router-synthesizer split"; a reported r/AI_Agents post describing an 8-tool agent's cloud bill cut 75% via a cheap classifier feeding a premium synthesis model; an April-2026 arXiv measurement study (2604.12301) naming "single-stage local/cloud router" as tactic T1 among seven cost-cutting tactics for coding-agent workloads (found via WebSearch).
- **Why it looks unbuilt/untested**: Practitioner caveats surfaced in the same WebSearch results say per-token savings were real but "the cost of debugging time to diagnose silent failures exceeded them in the first month," and an NVIDIA-cited analysis states teams "need custom routing and error handling built from scratch before any production deployment is viable" — every example found is a bespoke, single-team implementation, not a reusable packaged router/fallback layer.
- **Maturity**: SATURATED
- **Verdict notes**: GitHub search (`gh search repos "llm router"`) turned up a dense, actively-maintained field: BerriAI/litellm (63.2k stars, pushed same day, ships cost tracking, guardrails, load balancing, and fallback/logging exactly aimed at the "silent failure" caveat), lm-sys/RouteLLM (5.7k stars, a well-resourced lab, though stale since Aug 2024), NVIDIA's own `llm-router` blueprint, plus a wave of newer entrants (katanemo/Plano, ulab-uiuc/LLMRouter, NadirClaw, UncommonRoute, OrcaRouter-Lite) all shipping routing + fallback as a packaged layer. WebSearch corroborated with NVIDIA Switchyard (vendor-reported 74% cost cut) and LiteLLM's built-in fallback/observability. The specific "no reusable error-handling layer" framing is already undercut by LiteLLM's maturity and reach.

### P2: No hardening pattern for small local models' heightened prompt-injection exposure in agent stacks
- **What it is**: The specific claim that small models used as agent-stack components are more vulnerable to prompt injection and adversarial inputs than large frontier models, because they are less trained on adversarial data — surfaced as a caveat on router/cascade architectures rather than its own thread.
- **Evidence**: WebSearch synthesis (query: `local small model router agent cost savings cloud API 2026 reddit`) surfaced the practitioner-caveat line "Small models are more susceptible to prompt injection — they're less trained on adversarial inputs," cited alongside the cost-routing caveats above.
- **Why it looks unbuilt/untested**: Flagged only as a passing caveat in cost/routing discussions; no dedicated tool, benchmark, or mitigation pattern for small-model-specific adversarial hardening surfaced anywhere in this run's evidence — a named risk with no visible countermeasure.
- **Maturity**: PARTIAL
- **Verdict notes**: WebSearch found more activity than the digest's caveat implied, but it's fragmented research, not a packaged mitigation: Hermes Labs' "little-canary" (open-source decoy-model defense, self-reported 69.2%→98.6% refusal lift on a 208-prompt set), CourtGuard (arXiv 2510.19844, multi-agent small-model classifier), Meta's SecAlign adapters (8B/70B, open research code), and an academic SecFid paper (ICML 2026 Spotlight) critiquing how injection defenses are even measured, plus several Brazilian red-teaming papers on Qwen2.5-1.5B/SmolLM2 showing 45-62% attack success rates. No single maintained, productized hardening layer purpose-built for small-model-in-agent-stack deployments exists yet — a serious build combining these research threads into a deployable guardrail would be differentiated.

- **Evidence**: GitHub issue `qzyu999/ContainerClaw#8`, "Explore local model swarms with verifier-guided search and test-time compute" — explicit north-star goal quoted in the issue: "develop a coordinated swarm of smaller models that matches or exceeds Claude Opus 4.6 across the full set of relevant benchmarks on a 128GB local machine" (0 reactions, 2 comments, 2026-10-15).

- **Maturity**: SATURATED
- **Verdict notes**: WebSearch confirmed the HN item: reports describe Apple's "Harbor" Mac app (pools unified memory across Thunderbolt 5 Macs to run local open-weight models with no cloud dependency), currently in limited testing with public launch expected "in the coming weeks and months," alongside Apple's already-shipped Core AI / Foundation Models framework from WWDC 2026. ### P8: No multi-maintainer pipeline for independently reproducing community ultra-low-bit (1-bit/1.58-bit) quantized model builds
- **What it is**: The ultra-low-bit quantization niche (1-bit / 1.58-bit models, e.g. a "Ternary Bonsai" family) and community-built GGUF quants for running larger models on constrained VRAM (e.g., a ~27B-class model quantized to fit 16GB cards with KV-cache quantization), where availability currently depends on one maintainer's output.
- **Evidence**: WebSearch (query: `site:reddit.com r/LocalLLaMA "I wish" OR "has anyone built" small model quantization 2026`) surfaced a May-2026 third-party analysis of 265 r/LocalLLaMA posts citing a complaint that "only the author's own GGUF quants were available and hoped others would follow" (via a Reddit-mirror source), alongside references to the "Ternary Bonsai" 1.58-bit model family and a community quant of a ~27B model for 16GB cards.
- **Why it looks unbuilt/untested**: The named complaint is explicitly about single-point-of-failure distribution — one person's quant output being the only available version of a popular format, with no visible independent/parallel reproduction pipeline in the evidence found.
- **Maturity**: PARTIAL
- **Verdict notes**: WebSearch found the general community multi-maintainer quant culture is mature — mradermacher, QuantFactory, and individual accounts (mav23, kousw) already independently publish parallel GGUF quants of models like bitnet_b1_58, and tooling exists (AutoGGUF variants, llama.cpp's quantize script) — so the "no pipeline at all" framing overstates it. But ultra-low-bit/ternary-specific support genuinely lags: Prism ML's own Ternary-Bonsai-8B-gguf card notes Q2_0 isn't yet in mainline llama.cpp, meaning the tooling that *would* let independent maintainers reproduce this specific niche cleanly isn't fully there yet. Real gap remains narrow and format-specific rather than structural — PARTIAL, not SATURATED or OPEN.
