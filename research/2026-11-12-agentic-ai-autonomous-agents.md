- **Maturity**: SATURATED
- **Verdict notes**: WebSearch found at least seven well-resourced 2026 commercial launches squarely on this gap — Operant AI "Agent Protector" (continuous reauthorization by intent/behavior), Jozu Agent Guard (March 2026, zero-trust AI runtime), P0 Security (per-action access evaluation, shown at Identiverse 2026), Lineation.ai (July 2026, zero-trust control plane for autonomous agents), Xage Security (May 2026), Delinea (July 2026, pre-execution runtime authorization), and Arcjet (Sept 2026, per-action allow/block/redact/hold). - **Why it looks unbuilt/untested**: Coverage describes this as a bespoke internal build (Uber) and a platform-level feature rollout (Cloudflare) rather than a reusable open pattern/tool a smaller team could adopt — no general-purpose OSS equivalent surfaced in this run.
- **Maturity**: SATURATED

Multiple maintained, adoptable options exist, not just internal enterprise builds.

### P4: Hybrid "deterministic skeleton + agentic joints" workflow architecture

- **Evidence**: WebSearch secondary citation of r/AI_Agents discussion (via dev.to aggregator "A Field Guide to the AI Agent Debates Taking Over Reddit This Week") describing builders "settling on a hybrid model: deterministic skeleton, agentic layer at the joints," alongside threads on "when to use workflows versus agents."
- **Why it looks unbuilt/untested**: Described purely as an emerging community consensus/debate, not tied to any named framework or repo in the results — looks like a pattern people are converging on ad hoc rather than something packaged as reusable tooling.
- **Maturity**: PARTIAL
- **Verdict notes**: GitHub/web search found no single named framework packaging exactly this pattern as reusable tooling — only scattered, low-traction projects (Slater, Determ8, DAGonLayer on PyPI) and vendor blog framing (StackAI, TrueFoundry "deterministic vs. agentic workflows"). The underlying mechanics are already achievable ad hoc via mainstream orchestration frameworks (LangGraph graphs with agent nodes, Temporal + LLM activities), but no evaluated, purpose-built "skeleton+joints" product/repo surfaced — still a described community consensus, not packaged tooling.

### P5: Trace-level observability for agent production failures (vs. output-only evals)
- **What it is**: Instrumentation that captures full execution traces (tool calls, intermediate reasoning, retries) in production agents, so failures can be diagnosed causally instead of inferred from final output quality alone.
- **Evidence**: WebSearch result (labs.adaline.ai, "Building AI Agents That Don't Break in Production") stating "most production AI agents don't fail because the model is bad. - **Why it looks unbuilt/untested**: Articles recommend assembling point tools (Braintrust, Arthur, DeepEval, LangSmith) rather than pointing to one integrated solution — described as a practice/discipline gap, not a solved problem.
- **Maturity**: SATURATED
- **Verdict notes**: This is a mature, crowded product category, not a gap — LangSmith, Braintrust, Arize, and Datadog LLM Observability are established multi-year commercial products with real adoption, and GitHub turned up active fresh entrants too (traccia-ai/traccia-py, OTel-native, 134 stars, pushed 2026-11-10; AgentOps SDK).
