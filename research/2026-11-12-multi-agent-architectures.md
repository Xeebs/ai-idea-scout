### P8: Lightweight single-host multi-agent frameworks hitting a scaling wall
- **What it is**: A recurring framework-design pattern of role-based multi-agent routing plus checkpointing built on a single-host state store (e.g., SQLite), which is simple to adopt but cannot scale past one host — a tradeoff builders are making explicitly, not accidentally.
- **Evidence**: GitHub PR "Add LightAgent" (bloo-mind/awesome-multi-agent-systems, 2026-11-08) describing LightAgent as combining "role-based multi-agent routing, checkpoint[ing]" with an explicitly noted "single-host SQLite limitation"; a second GitHub issue (MaxonT/awesome-agent-workflows, 2026-11-08) suggesting the same project for an "Agent Frameworks" list.
- **Why it looks unbuilt/untested**: The limitation is called out directly in the project's own listing entry — it is a known, named gap (no multi-host/distributed state story) rather than something already solved by this or a competing framework in the results.
- **Maturity**: SATURATED
- **Verdict notes**: While LightAgent itself accepts the single-host limitation by design, WebSearch confirms the underlying scaling problem is already solved by well-resourced, maintained frameworks: LangGraph ships Postgres/Redis checkpointers for multi-host production state, Microsoft's AutoGen 0.4 Core API adopted a distributed, event-driven actor model letting agents run on separate instances, and the common production pattern layers LangGraph/OpenAI Agents SDK on durable workflow engines like Temporal. The specific gap (no path past one host) is closed elsewhere in the ecosystem, even though this one lightweight framework doesn't solve it itself.
