### P2: Context compaction silently destroys active task state (cross-tool reliability bug, not a one-off)
- **What it is**: Automatic context compaction/summarization in long-running coding-agent sessions repeatedly causes the agent to forget what it was actively doing — it keeps the system/environment framing but drops the in-flight task, then either stalls, loops, or reverts completed work.
- **Evidence**: GitHub issue on `openai/codex`, "Automatic compaction loses active task: continuation receives environment-only user context despite preserved rollout" (5 reactions, 17 comments per the engine run), with independent reproductions logged in-thread by three different users across Codex versions (including a separate Windows occurrence dated Oct 28, 2026, and a follow-up confirming recurrence on v0.165.0). WebSearch corroboration found the same failure mode reported repeatedly and independently elsewhere: OpenAI community threads "Automatic compaction does not trigger task-state recovery" and "Codex Desktop repeatedly loses the original acceptance goal after compaction," plus bug trackers titled "[Bug] Auto-Compact loses task context and reverts completed work without preserving last assignment" and "Auto-compact triggers mid-task causing context loss and hallucinations" on a separate agent tool.
- **Why it looks unbuilt/untested**: No vendor has shipped a fix — these are all open bug reports/forum threads describing the same failure shape across at least two different coding-agent products, and the workaround people describe is manual (git diff, handoff notes, starting a new thread), not a built-in safeguard.
- **Maturity**: OPEN
- **Verdict notes**: `gh search repos` for "task state checkpoint llm agent", "handoff artifact agent context", and "agent memory before compaction" returned zero results. WebSearch corroborated the digest's own finding and surfaced more of the same shape: OpenAI community threads ("Automatic compaction does not trigger task-state recovery"), a Codex GitHub issue requesting the agent preserve the last 5 operational steps verbatim, and multiple dev.to posts ("Compaction Amnesia", "Compaction is a Lossy Handoff") all proposing the same manual fix — write a handoff artifact / keep-list before compaction, or persist external state the agent re-checks each turn. Every proposed remedy found is a practitioner convention or a feature request, never a shipped plugin/tool that does this automatically.

### P3: Pinned, authority-tagged constraints that must survive compaction
- **What it is**: Treating certain instructions (user requirements, approval conditions) as a protected "contract" that a compaction/summarization pass is not allowed to silently drop, override, or let a later turn self-revoke without explicit authority.
- **Evidence**: GitHub PR on `bytedance/deer-flow`, "feat(summarization): align built-in compaction prompt to preserve user requirements and approval conditions" (2 reactions, 5 comments per the engine run). The PR's own review commentary names the specific mechanisms built ad hoc to patch this: a `_PINNED_CONSTRAINTS_CONTRACT` that treats prior user/project instructions as something only the user can revise, a "self-revocation prevention" fix, and a "PII redaction invariant" added only after a reviewer found a reproducible edge case.
- **Why it looks unbuilt/untested**: This is one team's bespoke, in-flight patch (multiple reviewer round-trips visible in the PR) to one project's compaction prompt — there is no shared library or pattern name for "authority-scoped pinned constraints," it's being reinvented per-repo in response to bugs, same underlying failure class as P2.
- **Maturity**: PARTIAL
- **Verdict notes**: `gh search repos` for "contract pinned constraint llm" and "self-revocation prevention llm instructions" returned zero results — no shared library exists. WebSearch found the pattern does have a name and active research behind it ("Constraint Pinning"), including an arXiv paper ("Governance Decay: How Context Compaction Silently Erases Safety Constraints in Long-Horizon LLM Agents") showing pinned-buffer constraints cut violation rate from 30% to 0%, a NeurIPS 2026 submission ("What Compression Preserves: Instruction Survival in Long-Horizon LLM Agents") reporting session-constraint retention as low as 17-40%, and a documented pattern writeup on agentpatterns.ai ("Per-Type Retention Policy for Agent Compaction"). This is real, de-risked signal (research-validated, a named pattern) but zero shipped, reusable implementation — every instance found is a one-off per-repo patch or a paper, matching the digest's own read.
