## The Gap
An r/MachineLearning poster (2026-11-12) described building, from scratch, a small model that tags intent, dialog act, entities, numbers, PII, profanity, and safety risk word-by-word as speech arrives, so a voice agent can react mid-sentence instead of waiting for a full turn to end: "We listen and type word by word, yet most AI only acts per turn. That wastes time and tokens, and it misses intent that was already clear halfway through the sentence." The gap-analyst's search confirms real prior art exists only in pieces — academic papers on incremental intent-closing or streaming slot-tagging — with nothing current, maintained, or bundling all these tag types into one streaming component. Every voice-agent team wanting this today has to hand-roll it, same as the original poster.

## The Project
A lightweight tagger that sits on a voice agent's streaming ASR output and emits structured tags — intent, dialog act (statement/question/command/backchannel), named entities, numbers, PII spans, profanity, safety-risk flags — incrementally as each word arrives, with a confidence score per tag that increases as more of the utterance is heard. A voice agent (or the speculative-tool-calling middleware already proposed elsewhere in this index) can subscribe to tag-confidence crossing a threshold and act before the speaker finishes — firing a lookup, flagging a safety-risk utterance for immediate escalation, or redacting PII before it's logged — instead of buffering the whole turn. The tagger is explicitly multi-tag (not single-purpose intent detection), since the original gap is that nobody bundles these together: a safety-risk flag firing mid-sentence matters as much as an intent firing mid-sentence, and today's point solutions handle at most one of these.

Components: a streaming adapter that normalizes partial-transcript events from 2-3 major ASR providers into one token-arrival event stream; a small fine-tuned sequence tagger (not an LLM call per token — needs to run at ASR speed) emitting the multi-tag output per token with running confidence; a per-tag-type threshold/action-trigger config; a replay harness that re-runs recorded conversations token-by-token to validate tag timing against ground truth.

## Tangible Impact
**Population**: Teams building production voice agents for latency-sensitive use cases — customer-support IVR replacements, crisis/support hotlines, and voice-first accessibility agents (several of which already exist as ideas in this index) — where every second of per-turn wait before the agent reacts is a measurable degradation in call experience or, in the crisis-hotline case, a safety-relevant delay.
**Mechanism**: Without this, a voice agent waits for end-of-turn (or a fixed silence timeout) before any tool call, safety check, or response planning starts, even when the relevant content was clear from the first half of the utterance — "I want to cancel my—" already signals intent before "subscription" finishes. A mid-sentence tagger lets the agent begin acting (pre-fetching data, flagging risk, routing) while the speaker is still talking, cutting the dead-air gap between end-of-speech and agent-response, and surfacing a safety-risk or PII flag the instant it's spoken rather than after the full turn is logged.
**Measure**: (1) Median time-from-intent-clear to agent-first-action, comparing mid-sentence tagging on vs. off, on a recorded conversation benchmark. (2) Tag-confidence calibration — how early (in tokens) a tag crosses a usable confidence threshold without false-triggering, across intent/safety-risk/PII tag types separately. (3) False-trigger rate (acting on a tag that reverses once the sentence completes) at the chosen threshold.

## Why Now
Streaming ASR providers (Deepgram, AssemblyAI, Azure) have made word-by-word partial transcripts a standard, low-latency feature over the past two years, and this index already contains a proposed speculative-tool-calling middleware for voice agents that needs exactly this kind of early, structured signal to decide when to fire — the ASR-side plumbing this tagger needs is mature; the multi-tag streaming model on top of it is the piece nobody has packaged yet.

## Skill Angle
A "Tag Taxonomy Architect" skill: given a description of a voice agent's domain (e.g., "support hotline for a telecom provider" or "crisis counseling intake line"), draft the specific intent/dialog-act/entity/safety-risk tag taxonomy and per-tag confidence-threshold policy the runtime tagger should use for that domain — including which tags should trigger an immediate action vs. only inform planning. This is a one-shot design task distinct from the always-running tagger itself, and is the same configuration work a team would otherwise do by trial and error against real call logs.

## MVP Sketch
A small fine-tuned sequence-tagging model (e.g., a distilled transformer under 100M params) trained on a public intent-classification dataset (e.g., a customer-support-intent corpus) re-formatted as a token-incremental task, wired to one ASR provider's streaming partial-transcript events, emitting intent + one safety-risk tag with running confidence. Experiment: replay 50-100 recorded support calls token-by-token and measure how many tokens before end-of-turn each tag's confidence crosses a usable threshold, versus a baseline that only tags at end-of-turn — if mid-sentence tagging doesn't meaningfully beat end-of-turn tagging in lead time without a spike in false triggers, the core hypothesis doesn't hold. 3-4 weeks, 1-2 people.

## Risks & Open Questions
- A sequence tagger accurate enough on partial, grammatically incomplete input is a nontrivial ML problem on its own — early-arriving tokens are inherently more ambiguous, and the false-trigger risk (acting on a tag that reverses once the sentence completes) could outweigh the latency win if not carefully thresholded.
- Bundling many tag types (intent, dialog act, entities, PII, profanity, safety-risk) into one small model risks each individual tag performing worse than a dedicated single-purpose model would — needs validation that the bundling is actually net-positive versus running several specialist taggers in parallel.
- If a major ASR vendor (Deepgram, AssemblyAI) ships this as a built-in feature on their own streaming API, a standalone cross-provider tagger's differentiation narrows to portability alone.
- The original r/MachineLearning signal is a single low-engagement personal project — worth validating demand with a second independent source before investing beyond the MVP.
