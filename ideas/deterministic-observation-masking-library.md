# Mask Don't Summarize: A Deterministic, No-Extra-LLM-Call Context Eviction Library for Long-Horizon Agents

- **Status**: EXPLORING
- **Date**: 2026-11-20
- **Topic**: Context engineering & memory
- **Source**: research/2026-11-20-context-engineering-memory.md · P2
- **Maturity verdict**: PARTIAL — real research backs the technique (JetBrains Research's "The Complexity Trap," arXiv 2508.21433, measuring observation masking roughly halving cost at matching/better solve rate vs. LLM-summarization compaction) and internal engineering teams (Atlassian's Rovo Dev, OpenAI's Codex team) have adopted structure-aware pruning/masking over compaction — but it's unpackaged. A June 2026 preprint proposing a formal lifecycle has no public code; the only shippable tooling found is a plain-FIFO Rust framework (`ambi`) and a 31-star Claude skill library. No mainstream, framework-agnostic, swappable library exists.
- **Format**: PROJECT — this is persistent middleware sitting inside an agent's context-assembly loop every turn; there is no separable one-shot judgment task distinct from running the deterministic rules themselves.
- **Data Sources**: CONNECTED — hooks into the agent framework's own tool-call lifecycle and context-window-assembly step (a stable extension point already shipping in the Claude Agent SDK, LangGraph, and comparable CLIs). No new external data source is read; the hook point exists maturely today, but no library implementing deterministic structure-aware masking on top of it exists yet.

## The Gap
Atlassian's Rovo Dev engineering blog and a DEV Community write-up (citing OpenAI's Codex team) describe structure-aware pruning and observation masking as faster and safer than the mainstream pattern of a blocking LLM call that summarizes history when the context window fills — the Codex team specifically found automated compaction "gradually hurt performance over time" because it lands mid-task, when the agent has the least budget to catch a resulting mistake. The underlying research is real and favorable (JetBrains' arXiv paper measures roughly half the cost at matching or better solve rate), but every team adopting it today is building its own internal version; no general-purpose, swappable library exists that other agent builders can drop in without re-deriving the eviction rules from scratch.

## The Project
A library that intercepts tool-call outputs before they re-enter context on later turns and applies deterministic, rule-based eviction — not a model judgment call — based on structural signals: output age (how many turns since last referenced), content type (raw log/search-result dumps mask more aggressively than short structured results), and a simple reference-tracking heuristic (was this output's content quoted or referenced in any later agent turn?). Masked content is replaced by a fixed placeholder (type + size + "N turns old, masked") rather than a summary, and unlike LLM-summarization compaction, nothing is paraphrased — the full original is still recoverable from the underlying log, only the live context view omits it. The centerpiece is that this never costs a model call: eviction decisions are rule-based and run in milliseconds, directly targeting the Codex team's finding that *model-driven* compaction mid-task is itself a source of errors.

Components: a tool-output interception hook (framework adapters for Claude Agent SDK and LangGraph first); a configurable rule engine (age/type/reference-tracking thresholds); a masked-placeholder renderer; an unmask/restore CLI for recovering a masked output on demand.

## Tangible Impact
**Population**: Teams running long-horizon agentic coding/research sessions (multi-hour, many tool calls) who have hit either compaction-induced cost/latency spikes or compaction-induced task regressions — the same population named in both the Atlassian and OpenAI Codex sources, but specifically the subset who haven't built an internal masking solution and are still on default LLM-summarization compaction.
**Mechanism**: Today, every context-window-full event either triggers an expensive, blocking, occasionally-inaccurate LLM summarization pass mid-task, or (for teams who've built their own fix) a bespoke internal masking script with no shared maintenance. A drop-in deterministic masking library removes the LLM call from the eviction path entirely, converting a cost-and-latency-and-risk event into a near-free, rule-based one — directly reproducing JetBrains' measured ~2x cost reduction at matched solve rate, but as adoptable infrastructure instead of an internal build.
**Measure**: (1) Token cost and wall-clock latency per long-horizon task session, masking vs. standard LLM-summarization compaction, at matched task-success rate (replicating JetBrains' own benchmark design on a held-out task suite). (2) Rate of "agent needed masked content back" recovery events via the unmask CLI, as a proxy for over-aggressive masking. (3) Number of compaction-triggered mid-task errors, before vs. after, following the Codex team's own named failure mode.

## Why Now
The research case (JetBrains' arXiv paper) and two independent production engineering teams (Atlassian, OpenAI) converging on the same technique within the last 30 days establishes real validated demand and feasibility; what's missing — a mainstream, swappable, framework-agnostic library — is a pure execution gap, not a research gap, making this buildable immediately with no new model capability required.

## MVP Sketch
A tool-output interception hook for one framework (Claude Agent SDK), an age+type+reference-tracking rule engine with sane defaults, and a masked-placeholder format. Experiment: reproduce JetBrains' benchmark design on a held-out suite of 15-20 long multi-tool-call tasks (log-triage, multi-file refactor), comparing token cost, latency, and task success against standard LLM-summarization compaction. If solve rate drops materially versus the token savings gained, the default masking thresholds need tuning before further investment. 2-3 weeks for 1-2 people.

## Risks & Open Questions
- A near-identical idea already in this index ("Prune Once," `ideas/model-judged-tool-output-pruning.md`) targets the same population with a *model-judged* per-output pruning approach — this project must stay clearly differentiated as the deterministic, no-extra-LLM-call alternative, and the two should eventually be benchmarked against each other, not just against baseline compaction.
- Rule-based eviction has no semantic understanding of what actually matters — a reference-tracking heuristic can miss content that becomes relevant only many turns later with no prior reference, risking the same "silently lost it" failure compaction already has, just via a different mechanism.
- A mainstream framework (Claude Agent SDK, LangGraph) could ship an equivalent built-in masking feature quickly once the pattern is named, as has happened to several comparable context-engineering ideas in this project's own backlog.
- The June 2026 "Beyond Compaction" preprint's lifecycle model is more sophisticated than plain masking and has no code — this project risks being outpaced by a more rigorous open-source implementation of that paper before it ships.
