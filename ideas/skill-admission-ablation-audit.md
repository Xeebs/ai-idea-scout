# Lift Check: A Pre-Admission Ablation Audit for Agent Skills Before They Join a Loadout

- **Status**: PROPOSED
- **Date**: 2026-11-13
- **Topic**: Context engineering & memory
- **Source**: research/2026-11-13-context-engineering-memory.md · P7
- **Maturity verdict**: PARTIAL — GitHub search for a general skill-admission audit tool found nothing dominant. WebSearch found only fragmented, narrow community skills attempting pieces of this (dbreunig.com's "Dr. Skill" loadout manager, a Claude Night Market "skills-eval" 5-dimension scorer, an HJewkes "context-audit" skill, a Tessl "context-budget" skill, a "b-open-io" Agent Auditor skill) — each small and independently published, not a converged standard. The source Google Cloud post is explicitly one vendor's internal methodology for auditing its own Cloud Developer Plugin skills, not a general reusable tool other skill authors can run.
- **Format**: BOTH — a quick heuristic review of a candidate skill's content is a one-shot judgment task; running an actual controlled ablation benchmark (with/without the skill, across repeated task trials) needs a persistent test-harness and, ideally, CI integration.
- **Data Sources**: Skill mode is MANUAL — the user pastes the candidate skill's full definition (its SKILL.md/instructions/tool-reference content) plus 2-3 representative task scenarios and the base model's current performance on them. Project mode is CONNECTED — integrates with the team's existing CI pipeline (e.g. a GitHub Actions workflow) and the host agent framework's own skill/tool registry to run repeated task trials with and without the candidate skill installed; no third-party API is needed, this reads directly from infrastructure the team already runs.

## The Gap
A Google Cloud blog post (Weinmeister & Blount, Nov 2026) names a methodology Google used internally on its own Cloud Developer Plugin skills across Claude Code, Google Antigravity, and OpenAI Codex: "when a test case shows identical success with zero efficiency gain, the base model already owns that capability natively... delete it," and skills that "copy-paste public API reference tables... yield almost no lift." This confirms a real, measurable failure mode — low-value skills silently bloating an agent's context budget — but the methodology is presented as one vendor's internal process for their own plugin, not a reusable audit tool. The gap-analyst's search found only a handful of small, independently-published community skills attempting pieces of this (loadout management, 5-dimension scoring, context-budget checks), none a converged, general pre-admission standard.

## The Project
A test harness and companion skill that runs a candidate skill through a controlled ablation: the same representative task set executed with the skill installed and without it, across the agent frameworks that matter to the team, reporting task-success delta and efficiency delta (tokens, turns, latency) per task. Skills that show zero lift get a clear "delete" recommendation with the evidence; skills that show real lift but are copy-pasted reference dumps get flagged as "low-density, consider converting to a thin router entry loaded on demand" rather than pasted in full upfront; skills that encode genuine compact operational habits or verification steps get a "keep, high-lift" verdict. The ablation methodology — turning Google's internal five-rule process into a runnable, repeatable test instead of a one-off internal review — is the centerpiece.

Components: a task-scenario runner (executes a defined scenario set with/without the candidate skill, across one or more agent frameworks); a lift scorer (success-rate delta, token/turn/latency delta); a density classifier (flags reference-dump-shaped skills using length-vs-lift ratio); a CI action that gates a new skill's admission into a shared loadout on a minimum lift threshold.

## Tangible Impact
**Population**: Skill authors publishing to Claude Code skill marketplaces (claudemarketplaces.com, claude-plugins.dev, skills.sh, Agensi) and engineering teams maintaining internal skill/tool catalogs for their own coding agents — both groups currently have no reusable way to answer "does this skill actually help, or is it just bloating every future agent's context window" before shipping it, the exact question Google had to build a bespoke internal process to answer for its own plugin.
**Mechanism**: Today, a new skill gets added to a shared loadout based on intuition or a one-off manual review (as Google's own team did), and low-lift skills — ones the base model already handles natively, or ones that are just pasted API reference tables — accumulate in the catalog, each one adding token cost and tool-selection confusion to every future invocation without ever being proven to help. A runnable ablation audit converts that intuition into a measured keep/delete/restructure decision before the skill ever reaches production, and a CI gate prevents the same mistake from recurring as new skills get proposed.
**Measure**: (1) Lift accuracy — does the audit's keep/delete verdict match a held-out human expert review, on a labeled set of known high-lift and known low-lift skills (including some built from the reference-dump pattern Google flagged). (2) Context-budget reduction — total tokens saved per agent invocation after removing audit-flagged low-lift skills from a real catalog. (3) Adoption outcome — for marketplace authors, whether skills that pass the audit before publishing see better review/retention signals than unaudited ones, over a tracked period.

## Why Now
Google's own team had to build and publish this methodology internally in the last 30 days specifically because no reusable tool existed for it, and the explosion of skill marketplaces (Agensi, claudemarketplaces.com, claude-plugins.dev, skills.sh) in 2026 means both individual authors and teams curating internal catalogs now face this exact admission decision repeatedly, with every existing response still a fragmented, small, independently-built community skill rather than a converged standard.

## Skill Angle
Given a candidate skill's full definition and 2-3 representative task scenarios with the base model's current (no-skill) performance noted, review the skill for the five failure signatures Google named: does it duplicate a capability the base model already has, is it mostly a reference-table dump, does it encode a genuinely compact operational habit, would a thin on-demand router entry work better than full upfront loading, and what's the net efficiency tradeoff. Produce a keep/delete/restructure recommendation with a one-line rationale per factor. Useful today as a fast pre-check before anyone commits to building the full ablation harness.

## MVP Sketch
A CLI that takes a candidate skill file and a small scenario set (5-10 representative tasks with success criteria), runs each scenario twice (with skill installed, without) against one agent framework (Claude Code), and reports success-rate delta and token/turn delta per task plus an overall keep/delete/restructure verdict. Experiment: run the harness against 5 real published community skills (mixing known-useful and known-reference-dump-shaped ones) and check whether its verdicts match a manual expert review. 2-3 weeks for 1-2 people.

## Risks & Open Questions
- Anthropic, Google, or a marketplace operator (Agensi, claude-plugins.dev) could ship a native pre-publish lift-audit requirement, which would be the most direct competitive risk given they already control the publishing surface.
- Ablation results can be noisy on small scenario sets or models with high run-to-run variance, risking false "no lift" verdicts for skills that genuinely help on rarer edge cases the scenario set didn't cover.
- The density classifier's "reference dump" heuristic needs validation against a range of real skills — a legitimately dense, compact skill could be misclassified as low-value by a naive length-based signal.
- It's unproven whether marketplace authors will actually run a pre-publish audit voluntarily without a platform-level incentive (visible audit badge, ranking boost) — adoption may depend on a marketplace partnership rather than the tool alone.
