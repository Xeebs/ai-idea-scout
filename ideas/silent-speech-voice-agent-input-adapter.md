# Quiet Channel: A Silent-Speech Input Adapter for Existing Voice-Agent Runtimes

- **Status**: EXPLORING (promoted 2026-11-13 cycle 60: evidence density — ≥2 independent threads within the digest, HN's "Ramble" Apple Watch launch and MIT Media Lab's muscle-reading wearable coverage both surfacing the same silent-speech-input gap independently)
- **Date**: 2026-11-13
- **Topic**: Voice & multimodal agents
- **Source**: research/2026-11-13-voice-multimodal-agents-ii.md · P8
- **Maturity verdict**: PARTIAL — confirmed research-grade implementations exist and are unevaluated for production use: SilentWear (ETH Zurich) is a fully open-source textile neck-EMG interface with on-device inference, reporting ~77.5% same-session but only 59.3% cross-session silent-speech accuracy; other EMG/piezo wearables (MDPI 2025 Sensors paper, a Pepabo/Yokohama National University hand-worn device) remain academic prototypes. No commercial smartwatch SDK or general silent-input layer that plugs into existing voice-agent stacks was found.
- **Format**: PROJECT
- **Data Sources**: CONNECTED — reads real-time signal streams from silent-speech wearable hardware via the device's own signal pipeline (SilentWear's open-source firmware/inference code is the most mature reference implementation available today, though it remains research-grade — there is no stable commercial EMG SDK yet, which is an honest limitation of this idea, not a gap this project can close on its own) and feeds normalized intent/text events into existing voice-agent frameworks' standard text-turn input (LiveKit Agents and Pipecat both already accept text-channel turns as an alternative to live audio — this half of the integration is mature today).

## The Gap
Two independent items surfaced in the same engine run: HN's "Show HN: Ramble – Message your agent directly from your Apple Watch" (2026-11-10) and MIT Media Lab coverage of muscle-reading wearables that "let you use voice input without speaking a word" (2026-11-06). Neither is a general input layer — Ramble is a single-purpose Show HN launch, and the MIT work is research/hardware coverage, not an SDK. The gap-analyst confirmed SilentWear is the one open, working implementation, but it is a standalone research demo with a steep same-session-to-cross-session accuracy drop (77.5% to 59.3%) and no integration into any voice-agent runtime.

## The Project
A middleware adapter that normalizes signals from silent-speech input sources — starting with EMG-class wearables (built on SilentWear's open pipeline) — into a standard intent/text event stream, and feeds that stream into existing voice-agent runtimes (LiveKit Agents, Pipecat) through their already-supported text-turn APIs, as a drop-in alternative to live microphone audio. The novel centerpiece is the adapter layer itself plus a cross-session recalibration flow designed specifically to push SilentWear's demonstrated 59.3% cross-session floor toward something closer to usable in a real multi-day deployment — closing the exact gap (accuracy decay across sessions) the original research flags as unsolved, rather than re-building the sensor from scratch.

Component list: EMG signal ingestion (built on SilentWear's open firmware/inference code), a short per-session recalibration routine, an intent-normalization layer, and adapters for LiveKit Agents' and Pipecat's text-turn input APIs.

## Tangible Impact
**Population**: People who cannot produce audible speech but retain residual muscle control sufficient for EMG-based silent speech — most directly, post-laryngectomy patients (the American Cancer Society estimates roughly 12,500 new laryngeal-cancer diagnoses per year in the U.S., a meaningful share of whom undergo laryngectomy) and people with ALS/motor neuron disease in earlier disease stages before full loss of bulbar/facial motor control (the ALS Association estimates roughly 30,000 Americans are living with ALS at any given time). Today this population has no way to use mainstream voice-agent products at all and is limited to slower AAC eye-gaze or switch-based text entry for anything requiring hands-free interaction.
**Mechanism**: A standard adapter means any voice-agent product a clinic, caregiver, or the person themselves already uses (a Vapi-built phone bot, a LiveKit-based assistant, a Pipecat voice app) becomes reachable via silent muscle signals instead of requiring a one-off bespoke integration per device and per app — the adapter is built once and reused across every downstream product that already speaks the text-turn protocol.
**Measure**: (1) successful command/intent recognition rate on a cross-session held-out test, tracked against SilentWear's own 59.3% cross-session baseline as the improvement target; (2) time-to-first-usable-command for a new user (minutes of recalibration, versus no path at all today since no integration exists); (3) number of distinct voice-agent platforms made reachable through one adapter instead of N bespoke one-off integrations.

## Why Now
The two halves of this integration are each independently mature today: SilentWear's open-source EMG signal/inference pipeline already exists and is usable, and mainstream voice-agent runtimes (LiveKit Agents, Pipecat) already accept text-turn input as a first-class alternative to audio — the only missing piece is the adapter and recalibration layer connecting them, which is buildable now with no new model capability required.

## MVP Sketch
2-4 week MVP: fork SilentWear's open signal-processing pipeline, train/calibrate it on a small fixed vocabulary (10-20 commands/phrases) with a handful of volunteer testers, build a thin adapter that converts classified intents into Pipecat text-turn events, and wire it into one simple Pipecat-based voice-agent demo (e.g. a basic appointment-scheduling bot). Single experiment: measure cross-session command accuracy for 2-3 volunteers across two separate days, with and without the project's own recalibration step, to see whether recalibration meaningfully narrows SilentWear's reported same-session/cross-session gap.

## Risks & Open Questions
- SilentWear's own numbers (77.5% same-session, 59.3% cross-session) are the honest starting point, not a solved problem — this project is a bet that a purpose-built recalibration flow can meaningfully close that gap, which is unproven until tested.
- Hardware access is a real bottleneck: this requires either building/sourcing a SilentWear-class EMG wearable or partnering with someone who has one; a pure-software MVP cannot validate the hardware-dependent accuracy claims.
- The target population (laryngectomy, early-stage ALS) has specific, varied residual-muscle profiles — a one-size-fits-all classifier may need per-user fine-tuning, which adds real deployment friction this idea does not yet solve.
- If a well-resourced accessibility-tech or AAC vendor (Tobii Dynavox, PRC-Saltillo) ships an equivalent voice-agent adapter first, the differentiation narrows to "open and hardware-agnostic" — worth monitoring given the accessibility-AAC market is more commercially organized than the general "silent input" hobbyist space.
