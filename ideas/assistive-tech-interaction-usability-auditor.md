# True Use: A Multimodal AI Auditor for Real Assistive-Tech Interaction, Not Just WCAG Markup

- **Status**: EXPLORING (promoted 2026-11-20 cycle 283: evidence density — ≥2 independent threads within the digest, WebAIM's 2026 report, the University of Maribor stability critique, and Silktide's 2026 commentary all independently confirming the same open 60-70% automated-accessibility-blind-spot gap)
- **Date**: 2026-11-20
- **Topic**: Applied AI for underserved domains
- **Source**: research/2026-11-20-applied-ai-for-underserved-domains.md · P6
- **Maturity verdict**: PARTIAL — one research prototype exists (ScreenAudit, arXiv 2504.02110, an LLM-driven Android TalkBack checker validated against 6 experts including a blind screen-reader user, outperforming existing rule-based checkers) and one vendor product announcement (AudioEye "Agentic Audits"), but a University of Maribor paper concludes LLM auditors "lack the stability and accuracy required to properly support human accessibility auditing," and Silktide's 2026 commentary says no scanner can yet judge whether alt text makes contextual sense — the underlying gap remains open per these sources.
- **Format**: BOTH
- **Data Sources**: CONNECTED — runs its own live interaction simulation against a target page/app using mature, widely-used automation stacks (Playwright/Chromium for browser automation, plus NVDA's and VoiceOver's own scripting/accessibility APIs where available) and an LLM for interaction-failure classification; no manual paste is required for the core workflow. A secondary manual path lets a user upload an existing manual-audit report to cross-validate the tool's findings against a human auditor's.

## The Gap
WebAIM's 2026 report (cited via IT Brief Australia) found automated testing "detects only about 30% to 40% of WCAG success criteria failures," against 95% of the top 1,000,000 homepages having at least one WCAG failure. Cognizant frames multimodal AI as "beginning to close" that gap by generating real-time descriptions of visual content, and Salesforce calls the remaining gap "a gap in process," not technology — but the sources agree the 60-70% automated blind spot is still open. ScreenAudit is the one real, validated attempt at closing it with AI, but it's scoped to a single platform (Android TalkBack) and a single interaction mode; a University of Maribor paper separately found LLM-based auditors unstable and inaccurate when asked to judge accessibility more broadly, and Silktide confirms no scanner can yet judge whether alt text makes contextual sense — leaving the gap this pattern targets explicitly unclosed outside ScreenAudit's narrow scope.

This project differs from this repo's existing `accessibility-scanner-divergence-gap-map` idea in mechanism, not just phrasing: that project builds a static, continuously-validated confidence lookup telling a user which WCAG criteria automated scanners can't be trusted on, so a human knows where to look manually. This project is the active tool that actually performs the deeper interaction-level test for the criteria that lookup would flag as "needs manual" — simulating a real assistive-tech user's interaction sequence and flagging failures with reproducible evidence, rather than telling someone a human still has to check.

## The Project
Generalize ScreenAudit's validated approach — an LLM-driven checker that reasons about actual interaction sequences, not just DOM/markup — beyond Android TalkBack to cover web screen-reader navigation (via NVDA/VoiceOver scripting), switch-control scanning order, and voice-control command coverage. Each run simulates a target interaction mode against a real page or app, and instead of returning a free-form LLM judgment (the exact brittleness the University of Maribor paper flags), it returns a structured, reproducible trace per failure: the specific interaction step, what a real assistive-tech user would experience, and the evidence (e.g., "tab order skips the search button," "the switch scan sequence never reaches the submit control," "no voice command matches the visible 'Cancel' action"). Stability is addressed directly, not assumed — every flagged failure is re-run multiple times and only surfaced if it reproduces, answering the stability critique head-on rather than ignoring it.

## Tangible Impact
**Population**: The roughly 61 million U.S. adults with a disability (CDC) who use assistive technology — screen readers, switch access, voice control — to navigate websites and apps, and the small-to-mid-size organizations maintaining the 95% of the top 1,000,000 homepages WebAIM found have at least one WCAG failure, who cannot afford a full manual audit for every release.
**Mechanism**: Catches the 60-70% of real usability failures automated scanners structurally miss (WebAIM's own figure) before a disabled user hits them in production, closing the specific gap Cognizant and Salesforce both describe as still open — without requiring a full-cost manual audit cycle for every release, and without the instability the University of Maribor paper found in less-constrained LLM auditors.
**Measure**: (1) agreement rate between the tool's flagged failures and an independent panel of real assistive-tech users doing manual testing on the same pages, replicating ScreenAudit's 6-expert validation methodology at larger scale and across the added interaction modes; (2) reproduction/stability rate of flagged failures across repeated runs on the same unchanged page, directly answering the Maribor paper's stability critique; (3) number of real interaction failures caught pre-release vs. a markup-only scanner baseline on a held-out test corpus of real sites.

## Why Now
ScreenAudit's arXiv-published, expert-validated methodology retires the core feasibility risk — an LLM-driven interaction checker can genuinely outperform rule-based checkers, at least on one platform — and mature browser/screen-reader automation APIs (Playwright, NVDA/VoiceOver scripting) make it newly tractable to generalize that same approach to switch-control and voice-control without building new instrumentation from scratch.

## Skill Angle
A companion skill: given a specific page or component description and the AI auditor's flagged failures, the skill drafts a targeted manual-test script for a human tester to follow for exactly the interaction paths flagged as high-risk — a lightweight, single-use companion for a team that wants a human to double-check a specific flagged issue without running the full live auditor.

## MVP Sketch
Scope to one additional interaction mode beyond ScreenAudit's Android TalkBack coverage — web keyboard/switch-control navigation, since it's more automatable via existing Playwright tooling than true voice-control intent matching. Port ScreenAudit's interaction-sequence-reasoning approach to a Playwright-driven switch-navigation simulator, add the repeat-until-stable verification step, and validate against a panel of 3-5 real switch-access users testing the same set of pages. Stack: Playwright for interaction simulation, an LLM for failure classification and evidence generation, a stability-check wrapper re-running each flagged failure before it surfaces. Validating experiment: does the tool's flagged-failure list agree with what the real switch-access testers actually experienced, and does the stability wrapper measurably reduce false positives compared to a single-pass LLM judgment.

## Risks & Open Questions
- The University of Maribor paper's stability/accuracy critique is the central risk this project has to actually overcome, not just claim to address — the repeat-until-stable design is a hypothesis, not a proven fix, until tested.
- AudioEye's "Agentic Audits" vendor product may already cover more of this ground internally than its public announcement discloses — worth direct evaluation of AudioEye's actual output before assuming a clean greenfield.
- Recruiting real assistive-tech users (switch-access, voice-control) for validation is a genuine operational cost and a known bottleneck across this entire problem space, not unique to this project.
- Generalizing beyond one interaction mode risks diluting the depth that made ScreenAudit's narrow TalkBack focus validated and credible in the first place — scope discipline in the MVP is a deliberate hedge against this.
