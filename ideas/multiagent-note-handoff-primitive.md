# Fresh Eyes: A First-Class Note-Handoff Primitive for Multi-Agent Frameworks

- **Status**: PROPOSED
- **Date**: 2026-11-20
- **Topic**: Multi-agent architectures
- **Source**: research/2026-11-20-multi-agent-architectures.md · P1
- **Maturity verdict**: OPEN — `gh search repos` for "agent note handoff" and "multi-agent asynchronous handoff" returned zero results. WebSearch found only a personal-project doc (spinchange/vulture-nest) describing a manual shared-note convention, plus Microsoft Agent Framework's and cortexai-crew's "handoff" features — both of which broadcast full conversation history to the next agent, the opposite of deliberately-severed context. No implementation of context-severing handoff as a first-class primitive found.
- **Format**: BOTH — the orchestration-mode library is PROJECT-shaped (it has to live inside a running framework's call graph), but deciding whether a given handoff should be note-mode or live-chat-mode, and drafting the note template, is a one-shot judgment task.
- **Data Sources**: BOTH apply differently by half — the **project** is CONNECTED: it wraps the host orchestration framework's own task/graph objects (crewAI `Task`/`Crew` context, LangGraph graph state, a raw agent loop's message list) via each framework's existing Python API — mature today for crewAI and LangGraph specifically — to intercept a handoff point and decide whether to pass the full history object or construct a fresh, history-free note object instead. No new external API is read; the integration surface is the framework's own already-exposed state. The **skill** is MANUAL: the user pastes a description of their two-agent pipeline (what Agent 1 produces, what Agent 2 is supposed to do with it) and the tool drafts the structured note template and a "fresh-context" review checklist for Agent 2.

## The Gap
An r/openclaw thread about getting two agents to collaborate in Telegram surfaced a concrete practitioner fix: "Works better if they don't actually chat in real time. Have Agent 1 write a structured note, then trigger Agent 2 to review it fresh with no shared conversation history." This is the opposite of how every mainstream handoff feature works today — Microsoft Agent Framework and cortexai-crew's "handoff" primitives both broadcast the full upstream conversation to the next agent, assuming more shared context is strictly better. The practitioner finding says the reverse is sometimes true: deliberately cutting the thread and forcing a fresh read reduces the second agent's tendency to just continue the first agent's frame (anchoring, inherited blind spots, echoed assumptions) rather than independently evaluating the work. No framework exposes "note-handoff mode" as a selectable, first-class alternative to the always-on shared-history mode.

## The Project
A small middleware/adapter layer — "Fresh Eyes" — that plugs into crewAI and LangGraph (with a generic adapter interface for others) and exposes handoff as a mode choice, not a given: `live-context` (today's default — full history passed through) versus `note-handoff` (Agent 1's turn ends by writing a structured note object — claim, evidence, confidence, open questions — and Agent 2 starts a genuinely fresh context window seeded only with that note, never the raw transcript). The library enforces the severing (so a careless adapter doesn't accidentally leak history back in), and ships an eval harness that runs the same two-agent task both ways and scores whether the second agent caught an error the first agent missed versus just rubber-stamping it — turning "works better" from an anecdote into a measured, task-dependent recommendation.

Components: mode-switchable handoff adapter (crewAI, LangGraph); structured note schema (claim/evidence/confidence/open-questions); a context-isolation enforcer (verifies no transcript leakage into "fresh" mode); the two-mode comparison eval harness with a scored "independent-catch-rate" metric.

## Tangible Impact
**Population**: Engineering teams building multi-step agentic pipelines on crewAI (~33k GitHub stars, self-reported use across roughly 60% of the US Fortune 500 per the project's own 2026 figures) and LangGraph (reported 34.5M+ monthly PyPI downloads) — specifically the subset running a producer/reviewer or generator/critic pair where the second agent's job is to independently catch what the first agent missed, not just continue its work.
**Mechanism**: Today every mainstream handoff defaults to full-history pass-through, so a reviewing agent inherits the first agent's framing and is measurably more likely to agree with it than catch its errors (the same "echo the upstream agent's hallucination" failure mode gap-analyst's P3 research describes in voting contexts, here showing up in sequential handoffs instead). Giving teams a selectable note-handoff mode — with an eval showing when it actually improves independent-catch-rate versus when live context wins — lets them pick deliberately instead of defaulting to "more context is always better."
**Measure**: (1) On the comparison harness, note-handoff mode's independent-catch-rate (does Agent 2 flag an intentionally-seeded error in Agent 1's output) measured against live-context mode's rate on the same seeded-error task set. (2) Time/token cost per handoff for each mode (note-handoff should show materially lower downstream context-window cost). (3) Adoption signal: at least one of the practitioner threads citing this workaround (r/openclaw) or a similar hand-rolled convention switches to the packaged adapter within 90 days of release.

## Why Now
Mainstream frameworks (Microsoft Agent Framework, cortexai-crew) just shipped "handoff" as a named feature in the last few months, making full-history pass-through the newly-visible default assumption — which is exactly the assumption the r/openclaw practitioner finding contradicts. That contrast is what makes this a timely, falsifiable idea rather than a stale observation: there's now a concrete default to measure against.

## Skill Angle
Given a description of a two-agent (or two-stage) pipeline — what the first agent produces and what the second agent is supposed to evaluate or build on — draft: (1) a structured note schema tailored to that specific handoff (claim, evidence, confidence, open questions, explicitly excluding raw process narration), and (2) a "fresh-context reviewer" prompt/checklist for the second agent that instructs it to evaluate the note on its own merits rather than asking for or inferring the first agent's reasoning trace. This is useful immediately, independent of whether the user adopts the Fresh Eyes library — it's a one-shot design task for anyone currently passing raw conversation history between two agent calls.

## MVP Sketch
A Python adapter for LangGraph only (simplest state model to intercept cleanly), the note schema as a Pydantic model, a manual context-isolation check (assert no upstream message objects reach the "fresh" call), and the comparison eval on 10 seeded-error tasks (code review pairs, research-summary-then-fact-check pairs). Experiment: if note-handoff's independent-catch-rate isn't meaningfully higher than live-context's on at least one task family, the practitioner anecdote doesn't generalize — scope the idea down to "sometimes useful, task-dependent" and ship the eval harness alone rather than the library. 2–3 weeks for 1–2 people.

## Risks & Open Questions
- Single-thread evidence (one r/openclaw reply, WebSearch-mediated, no direct engagement number available) — this could be one practitioner's idiosyncratic fix rather than a generalizable pattern; the MVP's eval is specifically designed to settle that before building more.
- The effect may be confounded with simple prompt discipline (a well-written note might help regardless of whether history is also present) rather than requiring severing per se — the eval must test note-with-history as a third condition to isolate the real variable.
- Framework maintainers could add a "summarize-only" handoff option natively (a much smaller change than a dedicated library) and absorb the core value here.
- LLMs may silently reconstruct or hallucinate "missing" context when given only a note, defeating the isolation guarantee in subtle ways that are hard to detect without the eval harness.
