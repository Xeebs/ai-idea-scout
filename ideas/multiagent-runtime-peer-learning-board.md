## The Gap
Hacker News surfaced "Peer Learning Between Agents in a Multi-Agent Team" (2026-11-06, github.com/Mininglamp-AI/Octo) — a low-engagement but on-point submission describing agents on the same live task learning from each other's successes and mistakes mid-run, distinct from offline multi-agent reinforcement learning. The gap-analyst's search found the cited repo doesn't resolve, but turned up two independent, real academic implementations (LessonL, PEEPLL) of essentially the same idea — confirming the pattern is a genuine, recently-active research thread with no production-grade, continuous, framework-agnostic version shipped yet.

## The Project
A shared "lesson board" that a team of agents collaborating on one live task reads from and writes to continuously, not just at the start or end of a run. When an agent's action fails and it then succeeds on a retry (or a human/verifier corrects it), the board captures the before/after as a generalized lesson — "when doing X, check Y first" — tagged by task type, and makes it immediately queryable by every other agent still working on related subtasks in that same run, not just in the next training cycle. Unlike LessonL's and PEEPLL's round-based/query-based designs, lessons propagate as soon as they're written, so a teammate three steps behind doesn't repeat a mistake that was already caught moments earlier in the same run.

Components: a lesson-write hook that triggers on detected fail-then-succeed patterns in an agent's trace; a lightweight lesson store scoped per run (not global, to avoid stale cross-run contamination); a pre-action lesson-check an agent consults before acting; a decay/expiry policy so lessons don't outlive their relevance within a run.

## Tangible Impact
**Population**: Teams running multi-agent systems where several agents work the same live task in parallel or in a pipeline — multi-agent coding-task fan-out, multi-step research/data-extraction pipelines, or multi-agent customer-support triage — the exact production shape LessonL and PEEPLL were built to study academically, now at the scale where a repeated mistake across agents on the same run has a measurable cost (wasted tokens, wasted wall-clock time, a second agent hitting the same wall the first one already climbed).
**Mechanism**: Without this, each agent on a shared task learns only from its own trial and error within its own context window — if agent A discovers that a particular API call needs a retry with different parameters, agent B doing a similar call later in the same run has no way to know and repeats the same failed attempt from scratch; a live lesson board turns one agent's hard-won fix into every other agent's free knowledge within the same run, not the next one.
**Measure**: (1) rate of repeated identical/near-identical failures across different agents within one multi-agent run, before vs. after the lesson board is active; (2) total tokens/wall-clock time spent on retries attributable to a mistake another agent had already solved in the same run; (3) task-completion success rate on multi-agent benchmarks (e.g., a multi-step coding or research benchmark run with several agents in parallel) with the board on vs. off.

## Why Now
LessonL (NeurIPS 2025) and PEEPLL (TMLR 2025) both landed as peer-reviewed, code-available research within the past year, proving the underlying mechanism (lessons generalized from one agent's experience and consumed by another, mid-collaboration) works well enough to publish — the gap is purely that nobody has taken it from round-based academic benchmarks to a continuous, framework-agnostic runtime component, which is now squarely an engineering problem, not a research one.

## Skill Angle
A "Lesson Extractor" skill: given one agent's raw trace of a failed action followed by a corrected/successful one, draft a generalized, task-type-tagged lesson entry suitable for broadcasting to teammates (what to check before attempting this action, what the failure signature looked like, what fixed it) — stripped of run-specific details so it transfers to a similar-but-not-identical situation. This is the one-shot drafting task underlying the board's write hook, useful on its own for anyone manually post-mortem-ing a multi-agent run before any live board exists.

## MVP Sketch
3–4 weeks, 1–2 people: build the per-run lesson store and the write/read hooks for one orchestration framework (e.g., a Python-based multi-agent fan-out script, matching the shape of P2's "lightweight orchestrator" complaints in this same digest), instrumented on a benchmark with repeated/similar subtasks across multiple parallel agents (e.g., a multi-file coding task fanned out to several coding-agent instances). Validate by running the same benchmark with the board on vs. off and measuring whether the repeated-failure rate across agents drops; if it doesn't drop measurably, the live-propagation design isn't earning its complexity over just reviewing failures at the end of a run.

## Risks & Open Questions
- LessonL's or PEEPLL's own authors could extend their research code into a production-ready, continuous version before this ships — the strongest already-adjacent risk, since both are active 2025 publications with maintained code.
- Per-run lesson scoping avoids stale cross-run contamination but also means lessons never accumulate across runs — worth validating whether teams actually want ephemeral (per-run) vs. persistent (cross-run) lessons before committing to the MVP's scope choice.
- Detecting a genuine "fail-then-succeed, generalizable lesson" pattern automatically (vs. noise, or a fix that only worked by coincidence) is itself a judgment call that could produce bad lessons that actively mislead teammates — needs a confidence/validation gate before broadcast, not auto-trust.
- The Octo repo cited in the original HN submission could not be confirmed to exist at all — worth re-checking in case it was simply renamed or made private, since its description matches this pattern closely and duplicate effort should be avoided.
