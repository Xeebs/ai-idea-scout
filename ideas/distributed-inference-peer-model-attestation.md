# Proof of Peer: A Lightweight Model-Substitution Attestation Layer for Volunteer P2P Inference Meshes

- **Status**: PROPOSED
- **Date**: 2026-11-13
- **Topic**: Small & local models
- **Source**: research/2026-11-13-small-and-local-models.md · P5
- **Maturity verdict**: PARTIAL — `Mesh-LLM/mesh-llm` PR #2981 ("feat(receipts): audit peer models with CommitLLM," 2026-11-10, 7 comments) is a first, single-PR attempt at a serving node signing a per-turn commitment to the model it ran. Serious, well-resourced prior art exists at enterprise/blockchain scale (Anthropic's FlashProve ZK proofs, Inference.net's shipped "LOGIC" statistical verification, the in-progress IETF draft-mw-spice-inference-chain, blockchain "Proof-of-Model" projects) but none of it targets small, hobbyist peer-to-peer mesh networks like Mesh-LLM or Petals-style hivemind forks — the gap-analyst found the general problem well-attacked but not adapted to this specific context.
- **Format**: PROJECT
- **Data Sources**: CONNECTED — the project is a protocol-level library that hooks directly into a mesh-inference project's own existing peer-to-peer transport (Mesh-LLM's gRPC protocol layer and its new CommitLLM commitment-signing primitive) to capture and verify each turn's computation receipt; no manual export or paste step for a mesh operator. The connector it depends on (Mesh-LLM's CommitLLM) is real but immature — a single open PR with 7 comments as of this digest, not yet a merged, stable API — so initial integration work should expect that surface to shift.

## The Gap
A GitHub PR on Mesh-LLM (2026-11-10) lets a mesh client check that a peer ran the model it claims rather than a cheaper quantization or a different model entirely, via a signed per-turn computation commitment — the first attestation hook inside a hobbyist distributed-inference codebase. Meanwhile Anthropic, Inference.net, an IETF draft, and several blockchain projects have all built serious verification machinery for the identical problem, but every one of them targets enterprise or blockchain-scale decentralized inference marketplaces running on datacenter GPUs, not a volunteer home-lab mesh running on consumer hardware. Nothing adapts the proven techniques down to the constraints (no GPU proof generation, tolerable-overhead statistical checks only) that a hobbyist mesh node can actually afford.

## The Project
A lightweight, protocol-level verification library for volunteer P2P LLM inference meshes with two tiers: (1) statistical consistency probing — inspired by Inference.net's LOGIC — where a mesh client occasionally sends a known challenge prompt and compares the peer's output against a precomputed fingerprint for the claimed model + quantization, catching substitution without requiring the client to re-run the model itself; (2) a cryptographic commitment layer that builds on Mesh-LLM's own CommitLLM pattern, so a node signs a hash commitment to each turn's computation that can be spot-checked later. A per-peer trust score, visible in the mesh client, aggregates both signals so clients can route around nodes with repeated mismatches instead of silently absorbing degraded answers.

Core components: (1) a challenge-prompt generator and reference-output fingerprint database for the handful of open-weight models/quant levels most commonly served on these meshes; (2) a client-side verifier that scores a peer's response against the fingerprint cheaply; (3) a per-peer trust-score ledger exposed to the mesh client UI/CLI; (4) a reference integration against Mesh-LLM, with Petals/hivemind-descendant forks as a stretch target.

## Tangible Impact
**Population**: Operators and users of small-scale, volunteer/peer-to-peer distributed LLM inference meshes — projects like Mesh-LLM and Petals-style hivemind networks that let home-lab GPU owners pool compute to collectively serve large open-weight models none of them could run alone. Petals (BigScience) had thousands of registered peers at its 2023 peak serving BLOOM-176B and Llama-2-70B; Mesh-LLM is a smaller, newer successor project in the same niche (digest evidence: PR #2981, Nov 2026). Size estimate: a low-thousands, recurring community of contributor-operators globally, not a one-off project.
**Mechanism**: Today any peer in these meshes can silently serve a cheaper or more aggressively quantized model than it claims — saving the operator compute and electricity cost — and the requester has no way to tell; a degraded answer just reads as "the model got this wrong." Proof of Peer gives mesh clients a verifiable per-turn signal, grounded in cheap statistical probing plus Mesh-LLM's own commitment-signing primitive, so substituting or cost-cutting peers get flagged and routed around instead of silently degrading every request that lands on them.
**Measure**: (1) detection rate of a deliberately substituted model/quant level in a red-team test harness (target ≥90% catch rate at ≤5% false-positive rate); (2) added per-turn latency/compute overhead on consumer hardware (target <10% — the ceiling volunteer nodes will tolerate before opting out); (3) adoption — number of independent mesh projects (Mesh-LLM, any active Petals/hivemind forks) integrating the library within 6 months of release.

## Why Now
Mesh-LLM's CommitLLM PR (Nov 2026) is the first native commitment-signing hook inside a hobbyist mesh codebase — previously these meshes had no attestation surface to build against at all. In the same window, Anthropic, Inference.net, and an IETF draft all validated that statistical and cryptographic verification approaches work at scale, de-risking the core technique; what's missing is simply the lightweight, no-GPU-proof-generation adaptation for consumer hardware, which is now buildable against a real (if immature) hook rather than from scratch.

## MVP Sketch
Scope: integrate with Mesh-LLM only (the one mesh project with an existing commitment-signing hook), implement tier-1 statistical probing for the 3-5 most commonly mesh-served open-weight models at 2-3 common quant levels, plus a trust-score display in the Mesh-LLM client. Stack: Python, hooking Mesh-LLM's existing gRPC protocol layer, a small reference-fingerprint database checked into the repo. Single validating experiment: stand up a 5-node test mesh, have one node deliberately substitute a smaller model, and measure whether the probe catches it within N turns at the target false-positive rate.

## Risks & Open Questions
- The population is genuinely small today — if hobbyist mesh inference doesn't grow past its current niche, the ceiling on real-world impact stays low regardless of how well the tool works.
- Statistical probing is gameable by an adversary who specifically targets known challenge-prompt fingerprints — this is an ongoing arms race, not a one-time fix, and the fingerprint database needs continuous maintenance as models and quant formats evolve.
- Mesh-LLM is a young, single-PR-stage project; building tightly against its current API risks a rewrite if the project's protocol changes or the project itself stalls (the same stale-single-maintainer risk the gap-analyst already flagged elsewhere in this digest).
- It may be more honest to wait and build only the heavyweight cryptographic tier once ZK proof generation (e.g., FlashProve) gets cheap enough to run on consumer GPUs, rather than over-investing in a statistical tier that could be a stopgap — worth monitoring that cost curve before committing to the lighter approach as the long-term answer.
