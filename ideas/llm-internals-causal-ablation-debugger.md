# Cut And See: An Interactive Causal-Ablation Debugger for Local LLM Internals

- **Status**: PROPOSED
- **Date**: 2026-11-20
- **Topic**: LLM evaluation & observability
- **Source**: research/2026-11-20-llm-evaluation-observability.md · P6
- **Maturity verdict**: PARTIAL — a real but fragmented adjacent landscape exists: `interp-lab` (PyPI, causal ablation/patching/steering with run manifests), 4+ distinct repos independently named `NeuronScope` (none canonical/widely-starred; the closest, `RudrenduPaul/NeuronScope`, is a CLI+MCP server built on TransformerLens, not a 3D interactive GUI), `GLUScope` (neuron-level analysis, no ablation UI), `IRTK` (JAX/Equinox, ablation among 170+ modules, visualization unclear), and established libraries `TransformerLens`/`SAELens`/`circuit-tracer` (programmatic, no confirmed interactive 3D ablation GUI). NeuronDump itself (the pattern's source, a 3-point Show HN) is a real but very early, low-traction attempt at exactly this combination. No settled, widely-adopted tool executes the specific "interactive 3D graph + cut + observe" workflow well.
- **Format**: BOTH — the interactive visualizer requires a running local session with the model loaded in memory and live state (clicked ablations, test-prompt re-runs), which is infrastructure-shaped; a one-shot "explain what this ablation result implies" judgment is a separable task.
- **Data Sources**: MANUAL — the user loads their own local model checkpoint (GGUF/safetensors) and supplies their own test prompts to probe against it. No external API or connector applies: the entire point is local, self-hosted debugging of a model the user already has on disk, with no data leaving the machine.

## The Gap
Show HN "NeuronDump: Open a local LLM as a 3D graph, cut parts, see what breaks" (github.com/aymen94/NeuronDump, 2026-10-25, 3 points) sketches exactly this workflow but at very low traction and, per the fragmented landscape above, with no confirmed maintained competitor doing the same combination well. The mechanistic-interpretability tooling ecosystem has mature *backend* ablation/circuit-discovery libraries (TransformerLens, interp-lab, several early NeuronScope-named projects) but none of them pair that backend with a polished, interactive, click-to-ablate 3D visualization a non-interpretability-specialist could actually use to debug a specific model problem.

## The Project
A debugging tool for people fine-tuning or modifying local/open-weight LLMs who hit unexpected behavior (a bad fine-tune, a weird regression after a model merge, a suspicious response pattern) and want to interactively isolate which component is responsible, without first becoming an interpretability researcher. It loads a local checkpoint, renders its architecture as an explorable 3D graph (layers, attention heads, key MLP neurons), lets the user click a node or edge to ablate it, and immediately re-runs a supplied test prompt to show the behavior delta — using existing mature ablation backends (TransformerLens or interp-lab) under the hood rather than reimplementing the mechanics, with the actual contribution being the interactive, reproducible, save-and-share-able debugging loop around them. Every ablation session produces a manifest (what was cut, what prompt was run, what changed) that can be re-run or shared for review.

## Tangible Impact
**Population**: local/open-weight LLM fine-tuners and hobbyist-to-small-team model developers (the single-GPU, consumer-hardware audience this digest's "Small & local models" topic repeatedly surfaces) who need to debug a specific behavioral regression in a model they've modified, rather than frontier-lab interpretability researchers already served by programmatic TransformerLens-style workflows.
**Mechanism**: turning "my fine-tuned model does something weird and I don't know why" into an interactive, visual process of isolating the responsible component converts a debugging task that today requires either interpretability expertise or guesswork into something a motivated non-specialist can do themselves, with a saved manifest they can act on or hand to someone who can.
**Measure**: time from "notice a behavioral regression" to "identify a specific responsible component or rule it out," measured against a baseline of manual/ad hoc debugging; number of ablation sessions that produce an actionable, reproducible finding (vs. inconclusive); user-reported confidence in the diagnosis before vs. after using the tool, on a small structured eval set of known-cause regressions.

## Why Now
Local fine-tuning and model-merging have become common enough on consumer hardware that behavioral-regression debugging is now a recurring need outside specialist interpretability teams, and the backend libraries this tool would wrap (TransformerLens, interp-lab) are already mature enough that building the missing interactive layer, not new interpretability mechanics, is the actual remaining work.

## Skill Angle
Trigger: a user already has ablation results (from this tool, a manual TransformerLens script, or any other source) — a description of what was cut and how the model's output changed — and wants help interpreting what that implies about the model's internals. Inputs: the ablation manifest (component removed, before/after output on a test prompt) and any context on what the user expected. Output: a plain-language explanation of the likely functional role of the ablated component and whether the observed change supports or weakens that hypothesis, plus a suggestion for the next ablation to try to narrow it down. This is the no-infrastructure companion to the interactive tool's live session — useful even for someone running ablations by hand.

## MVP Sketch
2–4 weeks, 1–2 people: wrap TransformerLens's ablation API for one small open-weight model family, build a minimal 3D graph renderer (even a basic force-directed layout is enough at MVP) with click-to-ablate and immediate re-run against a fixed test prompt set, and validate by reproducing a known, documented behavioral quirk in a small open model (ablating a head or neuron already identified in published interpretability work) and confirming the tool surfaces the same component through its own interactive flow.

## Risks & Open Questions
- The existing NeuronScope-named proliferation (4+ independent repos) suggests real community appetite but also real risk of this space converging on someone else's tool before this one ships — needs to differentiate on the interactive-3D-and-manifest angle specifically, not just "another ablation CLI."
- 3D graph visualization at the scale of a full modern model's layers/heads/neurons risks becoming visually unusable without careful filtering/level-of-detail design; this is a real UX problem, not a minor detail.
- Backend ablation operations (especially on larger local models) may be too slow for a genuinely interactive click-and-see loop on consumer hardware, which could force the MVP down to very small models only.
- "Debugging value" here is somewhat untested — NeuronDump's own 3-point reception suggests the target population may be smaller or harder to reach than the fragmented-tooling evidence implies; worth validating demand with a few target users before committing past the MVP.
