# Scope Trace: Authorization & Failure Propagation Across Agent Delegation Chains

- **Status**: EXPLORING (promoted 2026-11-12: ≥3 independent threads — MasDrift benchmark/arXiv 2608.07556, arXiv 2606.09692 observability-gateway paper, opencode-session-observability #4, luminous-platform #288)
- **Date**: 2026-11-12
- **Topic**: Multi-agent architectures
- **Source**: research/2026-11-12-multi-agent-architectures-ii.md · P5
- **Maturity verdict**: PARTIAL — a benchmark artifact exists (ZhuoningXu/MasDrift, backing arXiv 2608.07556, "Benchmarking Authorization Preservation Across Multi-Agent Architectures") and a second paper (arXiv 2606.09692) proposes an agent-aware observability gateway design, plus vendor/practitioner guidance (nhimg.org, Cedar-based layered-policy writeups) on re-checking scope per hop — but GitHub search ("agent delegation chain observability", "subagent failure propagation") and WebSearch found no shipped tool that implements authorization-preservation *and* failure-propagation together. The clearest live evidence is an open feature-request issue against a real observability tool (NicoGenti/opencode-session-observability #4) asking for exactly this and not yet built.
- **Format**: BOTH — the tracing middleware + observability store is PROJECT-shaped (must persist session/scope state between hops); auditing one existing delegation chain's code for where scope or failures could silently leak is a one-shot review task. See Skill Angle.
- **Data Sources**: CONNECTED — reads the agent framework's own session/delegation logs directly (e.g., OpenCode's session store, Claude Code subagent transcripts, LangGraph checkpoint state) via the framework's existing session API; no mature standard connector exists yet for "delegation chain + scope" specifically, so the first integration (OpenCode, the framework named in the evidence) would need a purpose-built adapter, with the same pattern then ported to other frameworks' own session APIs as later adapters — not a manual paste-in product.

## The Gap
GitHub issue NicoGenti/opencode-session-observability #4 (2026-11-09) states plainly: "In OpenCode 2 multi-agent architectures, tasks are frequently delegated via subagent tool calls producing child sessions... Currently, ObservabilityService.loadDataset processes each session in isolation, meaning subagent failures are invisible" to the parent. A second GitHub issue (Luminous-Dynamics/luminous-platform #288, 11 comments) tasks a team with reproducing the MasDrift benchmark specifically to study this same problem academically. Both are open, unresolved, dated within the last 30 days — the gap is real and nobody has shipped the fix, only described it or benchmarked it.

## The Project
A tracing middleware that sits inside an agent framework's delegation path (starting with OpenCode, the framework named directly in the evidence) and does two things every existing session observability tool treats separately or not at all: (1) it attaches an immutable authorization-scope token to every delegation hop, so a parent can always answer "what privileges did this child session actually have, and did it try to exceed them?" instead of trusting that the child inherited scope correctly; (2) it propagates a child session's failure or scope-violation signal up to the parent's observability view in real time, instead of each session being evaluated in isolation (the exact `ObservabilityService.loadDataset` limitation named in the evidence). The MasDrift benchmark becomes the validation suite — the project's claim to work is proven by beating MasDrift's documented drift scenarios, not by self-report.

Components: a scope-token wrapper around the framework's delegation call; a cross-session failure-propagation bus; an observability dashboard view that renders a delegation tree with scope and failure status annotated per node; a MasDrift-benchmark runner reporting pass/fail per scenario.

## Tangible Impact
**Population**: Teams building production multi-agent systems on frameworks with subagent delegation (OpenCode, Claude Code subagents, LangGraph) who currently have no visibility into whether a delegated subagent silently exceeded its scope or failed without the parent noticing — the exact gap the opencode-session-observability maintainer is fielding a feature request for in the last 30 days, representative of any team running delegation-heavy agent fleets in production rather than single-agent prototypes.
**Mechanism**: Without this, a privilege-drifted or silently-failed subagent's bad output gets treated by the parent as a normal, trusted result — the parent has no signal to distinguish "child did its job within scope" from "child quietly did something it shouldn't have or failed partway" — so errors and scope violations propagate invisibly into whatever the parent does next; this project turns that invisible failure mode into a visible, alertable event at the exact hop it occurred.
**Measure**: (1) MasDrift benchmark pass rate (scope-preservation and drift-detection scenarios) before vs. after adopting the middleware; (2) mean time to detect a subagent scope violation or silent failure, from "never" (today's isolated-session baseline) to a bounded number of seconds; (3) in a pilot deployment, the fraction of delegation-chain incidents that the tool flags before they cause a downstream parent-level error, vs. the fraction only discovered after the fact via manual log inspection.

## Why Now
The feature request against opencode-session-observability and the MasDrift-reproduction task both landed inside the last 30 days, showing the gap is being actively worked on right now by at least two independent groups (a tool maintainer fielding the request, a team tasked with reproducing the benchmark) with neither having shipped a fix — the benchmark existing at all (vs. not existing six months ago) is what makes "prove it works" newly possible instead of relying on self-report.

## Skill Angle
A "Delegation Chain Scope Auditor" skill: given a multi-agent system's delegation code (the subagent-spawning calls and whatever scope/credential-passing logic exists today), identify every hop where authorization scope is implicitly trusted rather than explicitly checked, and every place a child session's failure has no path back to the parent's observability view — producing a prioritized list of the specific lines/call-sites to wrap with the middleware pattern. This is a one-shot code review distinct from the project, which is the actual tracing middleware running continuously inside the framework's delegation path.

## MVP Sketch
3–4 weeks, 1–2 people: build the scope-token wrapper and failure-propagation bus for OpenCode specifically (the framework named in the live evidence), instrument 3–4 of MasDrift's documented drift scenarios against it, and build a minimal dashboard showing a delegation tree with scope/failure annotations. Validate: run the MasDrift scenario suite with the middleware on vs. off and show a measurable gap in detection rate; if the middleware can't beat "do nothing" on MasDrift's own scenarios, the tracing isn't earning its complexity.

## Risks & Open Questions
- MasDrift and the observability-gateway paper (arXiv 2606.09692) could themselves spawn a reference implementation before this ships — the strongest already-in-motion risk, since both are active research threads, not abandoned.
- Every agent framework structures delegation differently; starting with OpenCode risks a tool too narrow to generalize unless the scope-token/failure-bus abstractions are kept framework-agnostic from the start.
- Real-time failure propagation adds overhead to every delegation hop; needs validation that the latency cost doesn't outweigh the observability gain in latency-sensitive agent pipelines.
- The opencode-session-observability maintainer may simply build this themselves inside their own tool, since the issue is filed against their own repo — worth checking in before duplicating effort.
