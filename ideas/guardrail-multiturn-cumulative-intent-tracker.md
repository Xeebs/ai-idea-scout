# Cumulative Intent: A Multi-Turn-Aware Guardrail Layer Against Gradual-Framing Jailbreaks

- **Status**: PUBLISHED (promoted 2026-11-13 cycle 49: evidence density — 4 independent sources within the digest: Lasso Security 36% bypass report, aggregate-review 100% bypass findings, a Reddit-sourced 12-turn attack report, and two independent arXiv papers)
- **Date**: 2026-11-13
- **Topic**: AI safety & guardrails in production
- **Source**: research/2026-11-13-ai-safety-guardrails-in-production.md · P3
- **Maturity verdict**: PARTIAL — THRD (arXiv 2606.01738, June 2026) is a training-free defense tracking cumulative intent across turns, and the Echo Chamber paper (NeuralTrust, Jan 2026) plus aggregate reviews document up to 100% bypass rates against Azure Prompt Shield and Meta Prompt Guard via gradual multi-turn framing. No shipped, widely-adopted guardrail product claims to have closed the segment-vs-context mismatch — only defense papers and vendor acknowledgments.
- **Format**: BOTH — the always-on middleware tracking cumulative intent across a live session is persistent runtime infrastructure; a one-time "is this transcript a gradual-framing attack" audit is a separable judgment task.
- **Data Sources**: CONNECTED — the middleware wraps the host application's own LLM chat-completion call (OpenAI/Anthropic Messages API or equivalent, already mature and already in use by every app it would protect) to read the full multi-turn message history as it passes through on every request; no new connector needs to be built, only an interception point. The companion skill's one-shot audit mode is MANUAL — the user pastes the full conversation transcript (all turns, in order) they want assessed.

## The Gap
Guardrail classifiers (Llama Prompt Guard, IBM Granite Guardian, Perplexity BrowseSafe, Azure Prompt Shield) score prompt segments in isolation, but the downstream LLM integrates the full multi-turn conversation — so an attacker who spreads harmful intent across many individually-benign-looking turns gets scored safe turn-by-turn while the model still "sees" and acts on the combined attack. Lasso Security reported a 36% bypass rate against Perplexity's BrowseSafe this way; aggregate reviews cite up to 100% bypass against Azure Prompt Shield and Meta Prompt Guard via character-injection/evasion variants; a Reddit-sourced report (via aiweekly.co) describes a 12-turn gradual-framing attack defeating an internal bot's signature-based defense. Multiple 2025–2026 papers (arXiv 2504.11168, THRD) keep re-documenting the same gap rather than any vendor closing it.

## The Project
A middleware layer that sits between the host app and the LLM provider, maintaining a running "cumulative intent score" across the session instead of re-scoring each turn independently. Each incoming turn is evaluated both alone (existing classifier behavior, unchanged) and in the context of a sliding window of recent turns summarized into a compact intent trace; the trace is updated incrementally (THRD-style, training-free) rather than re-processing the full transcript every turn, so latency stays bounded as conversations grow. When the cumulative trace crosses a risk threshold — even though no single turn did — the layer can block, flag for human review, or inject a clarifying challenge before the next model call goes out.

Components: per-turn classifier passthrough (reuses whatever the team already runs — Prompt Guard, Granite Guardian, etc.); incremental intent-trace updater; threshold/escalation policy; a benign-conversation calibration set to tune the threshold against false positives on legitimate multi-turn use (roleplay, iterative brainstorming, tutoring).

## Tangible Impact
**Population**: Engineering teams running customer-facing, multi-turn LLM chatbots on top of commercial guardrail classifiers who are currently blind to gradual-framing attacks — concretely, the operators of consumer companion apps, teen-safety-oriented products, and general-purpose assistants layered on Azure Prompt Shield, Meta Prompt Guard, or Perplexity BrowseSafe, where published bypass rates (36–100% depending on technique) mean the classifier is providing a false sense of coverage today. The end users most exposed are people interacting with those products across many turns, including minors on teen-safety products, who are the ones actually harmed when a gradual-framing attack succeeds.
**Mechanism**: Per-turn classifiers only ever see a slice of the conversation, so an attack that stays individually-innocuous per turn sails through every check while the model accumulates and eventually acts on the combined intent. Tracking cumulative intent incrementally closes exactly that blind spot without requiring a new foundation-model-scale classifier — it reuses the existing per-turn checks and adds the missing session-level signal.
**Measure**: block rate on a reconstructed benchmark of known gradual-framing/Echo-Chamber-style multi-turn jailbreak transcripts, compared against the per-turn-classifier-alone baseline (target: materially above the 0–64% baseline bypass-implied catch rate); false-positive rate on a benign multi-turn conversation set (roleplay, tutoring, iterative coding) to confirm the layer doesn't just become an aggressive multi-turn censor; added p95 latency per turn versus the per-turn-only baseline.

## Why Now
THRD (June 2026) just published a training-free method for exactly this cumulative-tracking problem, and the Echo Chamber paper (Jan 2026) plus Lasso Security's BrowseSafe findings gave the industry a concrete, recent, quantified reason to care — the technique exists in research form, but nothing packages it as a drop-in middleware layer a team can wrap around whatever per-turn classifier they already run.

## Skill Angle
Trigger: a security or safety engineer has a suspicious multi-turn transcript (from an incident report, a red-team exercise, or a user complaint) and wants to know whether it's a gradual-framing jailbreak before deciding whether to invest in the always-on middleware. Inputs: the full conversation transcript, pasted turn-by-turn, plus (optionally) which per-turn classifier was already in use. Output: a turn-by-turn breakdown flagging where intent accumulated versus where any single turn would have tripped the existing classifier, a verdict on whether this matches known gradual-framing patterns (Echo Chamber, 12-turn framing), and a recommendation on threshold tuning if the team adopts the full middleware. The skill is the one-time forensic read; the project is the live session-level tracker.

## MVP Sketch
A lightweight Python proxy that intercepts chat-completion calls, maintains a per-session rolling summary (updated via a cheap incremental prompt against the last N turns plus the running summary, not the full transcript each time), and scores that summary against a risk threshold before forwarding the request. Single experiment: replay a reconstructed set of 20–30 known multi-turn jailbreak transcripts (from published papers/aggregator reports) plus 20–30 benign multi-turn conversations through the proxy with a chosen per-turn classifier both with and without the cumulative layer, and show the layer catches a meaningfully higher share of the attacks without pushing the benign false-positive rate materially up. 3 weeks, 1–2 people.

## Risks & Open Questions
- The incremental-summary approach itself could be gamed by an attacker who frames turns to also manipulate the running summary, not just the per-turn classifier — needs adversarial testing against summary-poisoning, not just the original multi-turn corpus.
- No public benchmark of multi-turn jailbreak transcripts is standardized yet; the MVP has to assemble one from scattered paper appendices and aggregator reports, which risks a small, non-representative eval set.
- A well-resourced guardrail vendor (Lakera, Azure, Meta) could ship a native multi-turn-aware mode before this reaches adoption, given how publicly documented the gap now is.
- Tuning the escalation threshold to avoid punishing normal long conversations (therapy-style companions, iterative coding sessions) is a genuinely hard calibration problem, not just an engineering one.
