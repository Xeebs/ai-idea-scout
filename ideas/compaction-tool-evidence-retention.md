## The Gap
Two unrelated GitHub PRs in the last 30 days — `onyx-dot-app/onyx`'s "retain tool evidence until context compaction" and `AstralBeamAI/astralbeam`'s default-on TanStack AI compaction middleware — are independently patching adjacent slices of the same underlying problem: naive compaction summarization flattens tool outputs (diffs, command results, search hits) into lossy prose, discarding exactly the evidence later reasoning steps depend on. Neither PR shares an abstraction with the other, and WebSearch found only one general-purpose harness (TrueForge) that happens to architect around keeping a persisted event log separate from the model-facing compacted context — not a dedicated, benchmarked tool for this specific failure mode.

## The Project
A compaction wrapper that, before a summarization pass runs, writes every tool-call result verbatim to a local content-addressed evidence store keyed by a short reference ID, then instructs the compaction summary to cite evidence by ID ("see diff #a3f1") instead of paraphrasing its content inline. A lightweight resolver lets the agent re-fetch the verbatim artifact by ID on demand after compaction, so later reasoning can check the real diff/output instead of trusting a summary's lossy retelling of it. This is deliberately scoped to evidence *fidelity* — not task-state continuity (a sibling gap already covered by Task Anchor) and not trust/authority tagging against injected instructions (a sibling gap already covered by Provenance Seal) — making it a narrow, complementary layer rather than a competing architecture.

Components: a tool-call interceptor that writes each result to a content-addressed store (diff, stdout/stderr, search-hit payload, keyed by hash); a compaction-prompt modifier that asks the summarizer to reference stored evidence by ID rather than inline it; an evidence resolver tool the agent can call post-compaction to fetch the verbatim artifact; a confabulation-probe eval harness that plants a factual-recall question about an earlier tool output and checks whether the agent's answer matches the stored artifact.

## Tangible Impact
**Population**: Developers running long-horizon coding agents (Claude Code, Codex, Cursor) on real repositories across sessions that cross one or more automatic compaction boundaries — the same long-running-agent cohort evidenced in this digest's compaction bug reports, narrowed further to the subset whose downstream correctness depends on the exact content of a prior tool output (what a failing test's stack trace actually said, what lines a diff three steps ago actually changed), not just whether an approach was already tried.
**Mechanism**: Today, naive compaction paraphrases tool outputs into lossy prose, so when the agent later needs to reason about the literal content of a diff or command result, it either confabulates a plausible-sounding but wrong detail or burns time/cost re-running the tool just to recover information it already had once. A verbatim, ID-referenceable evidence store means the agent's later reasoning can cite or re-fetch the real artifact instead of operating on a paraphrase it has no way to verify.
**Measure**: (1) Confabulation rate — agent claims about a prior tool output that don't match the stored artifact — on a benchmark of long sessions with forced compaction plus a planted factual-recall probe, with vs. without the evidence store. (2) Rate of redundant tool re-execution purely to recover already-obtained information. (3) Evidence-store token/storage overhead as a percentage of total context budget, to confirm the fix doesn't just relocate the bloat it's meant to prevent.

## Why Now
Two unrelated teams built adjacent slices of this exact problem independently within the last 30 days, and TrueForge's shipped (if general-purpose and unevaluated for this specific job) separation of a persisted event log from lossy working context proves the architecture is already implementable today with current compaction-hook surfaces — nobody has packaged it as a dedicated, benchmarked tool.

## Skill Angle
Given a compacted session transcript plus the original tool outputs it was derived from (pasted or available from logs), review the compacted summary for evidence loss: flag specific claims that depend on a tool output's exact content but only cite a paraphrase, and reconstruct a corrected context block that reattaches the verbatim evidence where it matters most. Useful today as a one-off forensic check on a session that already produced a wrong answer after compaction, independent of whether the always-on evidence store is installed.

## MVP Sketch
A thin wrapper around Claude Code's PreCompact hook (the same hook surface `compaction-task-anchor` and `compaction-invariant-pinning-library` already target): intercept each tool-call result, write it to a simple hash-keyed local store, and modify the compaction prompt to reference stored IDs instead of inlining full content; add a resolver tool the agent can call to fetch an artifact by ID. Experiment: run 15-20 multi-hour coding sessions forcing 2+ compactions each, plant a probe question requiring exact recall of an earlier diff or command output, and measure confabulation rate and redundant-re-execution rate with vs. without the evidence store. 3 weeks for 1-2 people.

## Risks & Open Questions
- Anthropic, OpenAI, or Cursor could ship evidence-aware compaction natively — the same absorption risk already flagged on the sibling Task Anchor, Pin It, and Provenance Seal ideas, all competing for the same vendor-fixes-this-first window.
- Overlaps conceptually with Pin It's "already-tried approaches" invariant set and Provenance Seal's origin tagging; this project is scoped to content fidelity of tool outputs specifically, but a shipped vendor fix to either sibling gap could blur the remaining distinct value here.
- A content-addressed store that grows unbounded across a very long session could itself become a storage/retrieval cost problem without an eviction or TTL policy.
- "Reference by ID instead of inlining" only helps if the model reliably chooses to resolve the reference when it actually needs the content — if it reasons from the bare ID without resolving, the fix provides no benefit.
