# Full Coverage: A Combined Replay + Adversarial-Synthetic + Auto-Regression Test Harness for Voice Agents

- **Status**: EXPLORING
- **Date**: 2026-11-20
- **Topic**: Voice & multimodal agents
- **Source**: research/2026-11-20-voice-multimodal-agents.md · P4
- **Maturity verdict**: PARTIAL — each of the three layers has real but separate tooling: `voicetest` (Apache 2.0, PyPI-published) handles real-call replay only; `xray-eval/xray` replays under a non-OSI Elastic License; EVA-Bench/VAmoS-Bench are academic synthetic-adversarial benchmarks, not shipped products; Eve Legal's auto-promotion-of-failures-to-regression-tests is a proprietary in-house harness. No single open, adopted framework combines all three layers.
- **Format**: BOTH
- **Data Sources**: CONNECTED — ingests real call recordings/transcripts via the voice platform's own call-log/export API (Vapi, Retell, Bland, and LiveKit are all named in the digest's evidence as already having transcript/recording export, and `voicetest` already supports import from all four); synthetic adversarial callers are generated by an LLM with no external data needed. (The companion skill's input is MANUAL — see Skill Angle.)

## The Gap

A DEV Community post concretely demonstrates why one layer alone fails: replaying 312 recorded production calls as a regression suite missed a code-switching failure that "never appeared in the recordings" because it happens exactly once per caller. Vapi's own docs separately distinguish "Evals" from "Simulations" and recommend promoting production failures to regression tests, but as guidance, not tooling. `voicetest` replays; EVA-Bench/VAmoS-Bench simulate adversarially as research artifacts; Eve Legal auto-promotes failures but only in-house. Every builder doing this today is assembling the same three pieces from scratch, in a different combination, with no shared tool.

## The Project

A single harness with three integrated modes that feed each other: (1) **Replay** — imports real call transcripts/audio from a connected voice platform and re-runs them against the current agent graph (building on `voicetest`'s proven import coverage rather than reinventing it); (2) **Adversarial synthesis** — an LLM-driven simulated caller generates inputs targeting known failure classes (code-switching, DTMF confusion, backchannel noise) that real recordings haven't yet surfaced, closing exactly the gap the DEV Community post identified; (3) **Auto-promotion** — any flagged production failure (a thumbs-down event, a human-reviewed bad call) gets converted into a permanent, versioned regression case automatically, generalizing Eve Legal's proprietary pattern into a reusable pipeline. All three write to one shared test-case store so replay, synthetic, and promoted cases run in the same CI gate.

## Tangible Impact

**Population**: Engineering teams running production voice agents who, per the AssemblyAI 2026 Insights Report cited in this digest's own P2, are overwhelmingly (87%) already deployed but only 25% satisfied with real-call quality — a gap this harness targets structurally rather than through more dashboards. Scales with the 2026 voice-AI-agent software market estimated at $3.5–5.1B (Grand View Research, Meticulous Research).
**Mechanism**: A team stops manually re-deriving replay, adversarial, and promotion tooling separately (or skipping one layer entirely, as the digest shows most builders currently do) and instead gets regression coverage that compounds automatically every time a real failure is caught — the exact gap the 312-call example shows a replay-only suite can't close on its own.
**Measure**: number of previously-unseen failure classes caught by the adversarial layer that the replay-only set missed; time from a flagged production failure to a committed regression test (target: minutes via auto-promotion vs. the manual multi-day process most teams report); regression-suite catch rate on a held-out set of real incidents across a 90-day window.

## Why Now

Vapi's docs, `voicetest`'s PyPI release, and the academic adversarial-caller benchmarks (EVA-Bench, VAmoS-Bench) all landed independently within recent months — the raw pieces now exist publicly and mature enough to integrate rather than needing to be built from zero.

## Skill Angle

A "test gap triage" skill: given a pasted transcript of a voice-agent failure (real call or near-miss) and a brief description of the team's current test coverage, it classifies which of the three layers would have caught it, drafts the specific regression test case (input, expected behavior, assertion), and flags whether the failure class suggests a gap the adversarial-synthesis layer should be expanded to cover.

## MVP Sketch

Scope: wire `voicetest`'s existing replay/import layer to one LLM-driven adversarial-caller mode targeting 3 known failure classes (code-switching, DTMF confusion, interrupted mid-tool-call) and one auto-promotion hook off a thumbs-down webhook. Stack: Python, built on top of `voicetest`'s existing import adapters rather than reimplementing them, a shared SQLite/Postgres test-case store, CI integration via GitHub Actions. Validating experiment: run the combined harness against a real agent and confirm the adversarial layer catches at least one failure class the team's existing replay-only suite (if any) missed.

## Risks & Open Questions

- `voicetest`'s Apache 2.0 license is favorable, but building directly on it risks being seen as a wrapper rather than new value — differentiation must be the integration (auto-promotion + adversarial feed) not the replay mechanics.
- Adversarial synthesis quality depends entirely on how well the generator models real failure distributions; a poorly tuned generator produces noise, not signal — needs validation against the real 312-call dataset shape before trusting it on a new agent.
- Auto-promotion risks flooding the regression suite with noisy, one-off edge cases if the promotion criteria aren't disciplined (e.g. requiring human confirmation before permanent promotion).
- `xray-eval/xray`'s Elastic License (non-OSI) suggests at least one team already saw commercial value here and chose a restrictive license — worth checking whether that signals a harder monetization path than open tooling can sustain.
