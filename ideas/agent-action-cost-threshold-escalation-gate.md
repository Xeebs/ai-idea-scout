## The Gap
A real GitHub PR (pingdotgg/t3code #26254, 2026-10-28, 103 reactions / 25 comments) shows a review bot literally refusing to run because "this review would cost an estimated $26.45, which exceeds your per-review limit of $15.00," followed by "Verdict: Needs Human Approval" — direct, dated evidence that teams want expensive agent actions gated on cost estimate, not just on failure or timeout. But this exists today only as one vendor's internal workspace setting inside one product, and the only other GitHub matches are two single-digit-day-old, zero-adoption repos. No tool-agnostic, pluggable circuit breaker that estimates cost across arbitrary agent actions (not just one product's review feature) and routes to a human escalation queue exists yet.

## The Project
A middleware layer that wraps any tool-call-capable agent loop and, before a given action executes, estimates its likely dollar cost using a pluggable per-action-type heuristic (diff size and model pricing for code review, projected token count for an LLM call, a documented unit price for a metered API call). If the estimate exceeds a configured per-workspace or per-action-type threshold, the action is paused and routed to a human approval queue — instead of either running blind or simply aborting — with the pending action's full context attached so the human can approve, reject, or adjust and re-run. Once an approved action completes, its actual cost is logged against the estimate, continuously calibrating the estimator's accuracy per action type.

Components: a pluggable per-action-type cost estimator, a configurable threshold policy (per workspace, per action type, per session), a human-approval queue with full action context, and an estimate-vs-actual calibration ledger.

## Tangible Impact
**Population**: Engineering and ops teams running agentic workflows with metered, variable-cost actions — paid review bots, agents making paid third-party API calls, compute-heavy agent actions — who want a cost-based safety valve that escalates to a human rather than either running unconstrained or hard-blocking outright. The macroscopeapp[bot] example's 103 reactions / 25 comments on a single PR is direct evidence this specific need is already live and generating engagement in production teams today, not a hypothetical.
**Mechanism**: Without a pre-action cost gate, an agentic workflow either runs every action regardless of cost (exposing teams to the kind of $26-for-one-review surprise shown in the evidence) or is restricted by a single vendor's product-specific limit that doesn't generalize to any other tool the team uses. A pluggable, tool-agnostic estimator-plus-escalation layer lets a team set one cost policy across every metered action an agent takes, converting unbounded blind spend into either an approved expense or a declined one, with a human making the call on the exact cases that matter.
**Measure**: (1) Dollar amount of estimated spend intercepted and reviewed before running, split into approved vs. rejected-by-human, on a team's own action history. (2) Estimate accuracy — predicted vs. actual cost on approved-and-executed actions — tracked over time to confirm the calibration ledger actually improves estimator precision. (3) Escalation-queue latency and the % of escalations resolved within a defined SLA, to confirm the gate doesn't itself become the new bottleneck it was built to avoid.

## Why Now
The macroscopeapp[bot] incident landed inside this digest's 30-day window as dated, concrete evidence that at least one production team is already living with a cost-threshold gate — just one locked inside a single vendor's product rather than available as something any team can wrap around any agent action. The underlying mechanism (intercepting a tool call before execution) is already a stable extension point in every major agent SDK and MCP client today, so no new infrastructure primitive needs inventing, only the pluggable estimator-and-escalation logic on top of it.

## Skill Angle
Trigger: a user describes a pending agent action (what it does, rough scope/size, which paid API or model it would call) and wants a quick read on whether it should proceed, be flagged, or be escalated before anyone commits to the always-on middleware. Inputs: the action description, the relevant size/scope signal (diff size, estimated token count, per-unit price), and the team's threshold if known. Output: an estimated cost range, a recommended disposition (proceed / escalate / reject), and the reasoning, mirroring the live gate's logic as a one-shot pre-adoption check.

## MVP Sketch
A middleware wrapper for one popular agent framework (e.g., the Claude Agent SDK) plus direct MCP client interception as a second path, implementing cost estimators for two action types first — LLM-call token-cost estimation and a generic "price-per-call" metered-API estimator — with a simple threshold config and a human-approval webhook (Slack/email) carrying the pending action's context. Experiment: replay the macroscopeapp[bot] incident's described scenario (a $26.45-estimated review against a $15 limit) through the gate and confirm it escalates correctly, then run the gate against a week of a team's real agent-action history to measure estimate accuracy and false-escalation rate. 3–4 weeks for 1–2 people.

## Risks & Open Questions
- Per-action-type cost heuristics (especially for third-party APIs without transparent, predictable pricing) may be too noisy to estimate reliably before execution, undermining the whole premise.
- Too low a threshold turns the gate into a bottleneck that defeats agent autonomy's whole point; too high a threshold defeats the safety valve — tuning this per team is nontrivial and will need the calibration ledger to actually work.
- Agent-framework vendors could ship this as a built-in primitive (several frameworks already expose per-call cost metadata), narrowing a standalone tool's differentiation to cross-framework portability and the human-escalation-queue UX specifically.
- Overlaps conceptually with reactive, failure-pattern-based circuit breakers already proposed in this index (e.g. `agent-tool-call-cost-circuit-breaker.md`) — this project must stay clearly upfront/proactive (estimate-before-run, escalate-to-human) rather than drifting into that idea's reactive repeated-failure-detection territory.
