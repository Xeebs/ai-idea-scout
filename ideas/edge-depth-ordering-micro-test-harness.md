# Depth Check: A Near/Far Ordering Micro-Test Harness for Edge Depth-Estimation Models

- **Status**: PROPOSED
- **Date**: 2026-11-19
- **Topic**: Small & local models
- **Source**: research/2026-11-19-small-local-models.md · P9
- **Maturity verdict**: OPEN (genuine multi-channel search — GitHub, web, Qualcomm's own model cards — found only the open feature request itself; no existing pairwise depth-ordering correctness test or harness surfaced)
- **Format**: PROJECT
- **Data Sources**: MANUAL — the developer points the harness at their own depth model (an ONNX/TFLite/local inference endpoint running on-device or in an emulator) and the harness runs it against a bundled, versioned corpus of scene image pairs with pre-established ground-truth near/far ordering that ships with the tool, growing by community contribution over time. A CONNECTED upgrade is plausible later — pulling models directly from Qualcomm's AI Hub Models catalog via its public listing — but no mature API for third-party automated testing against that catalog exists today, so this stays MANUAL for the MVP.

## The Gap
A Qualcomm AI Hub Models contributor opened an issue proposing exactly this check against Depth Anything V2 on Snapdragon — "a depth map can look convincing even when two objects have swapped order" — and explicitly asked to contribute "a small example that catches that error" (2 reactions, 4 comments, 2026-11-14). The gap-analyst's multi-channel search (GitHub, web, Qualcomm's own model documentation, a Hackster.io deployment write-up) found only general latency/accuracy benchmarks for edge depth models — nothing that specifically tests pairwise near/far ordering correctness, a failure mode that's invisible to standard depth-error metrics (RMSE, delta-thresholds) because they average over the whole map instead of checking relative order between specific objects.

## The Project
A small, versioned, open test corpus of scene pairs (two or more objects with an unambiguous, human-verified near/far relationship) plus a harness that runs any depth model against each pair and flags cases where the model's own depth values invert the known ordering — even when the overall depth map "looks" plausible to a human skimming it. The harness reports a per-model, per-scene-category ordering-accuracy score (occlusion edges, thin objects, reflective/transparent surfaces, low-texture regions — the categories where monocular depth is known to be brittle), distinct from and complementary to standard depth-metric benchmarks. A CI mode lets a team re-run it automatically whenever they swap a model checkpoint or quantization level.

Core components: (1) the growing, community-contributable scene-pair corpus with ground truth captured via stereo rig or LiDAR reference, not just human eyeballing; (2) a model-agnostic runner wrapping common edge inference formats (ONNX Runtime, TFLite, Qualcomm QNN); (3) an ordering-violation scorer and category breakdown report; (4) a CI-friendly pass/fail gate with a configurable tolerance.

## Tangible Impact
**Population**: Developers shipping monocular-depth-dependent features on edge NPU hardware where a wrong near/far call has physical consequences — obstacle-avoidance robotics and drones, and AR navigation aids for blind and low-vision users (e.g., apps building on Qualcomm AI Hub's published Depth Anything V2 / MiDaS edge deployments, a catalog downloaded by thousands of edge-AI developers). This is a narrow but safety-adjacent developer population, not end-users directly, but end-users (a blind pedestrian trusting a navigation app's "the pole is closer than the car" judgment) are who absorbs a missed error.
**Mechanism**: Today a team validates a depth model with aggregate accuracy metrics that can look fine while hiding an ordering flip on exactly the objects a near/far judgment matters most for (a curb vs. a person two feet behind it). This harness surfaces that specific failure class before deployment, turning a silent, hard-to-reproduce field bug report into a caught pre-ship regression.
**Measure**: (1) number of distinct ordering-inversion cases caught per model/checkpoint during a pre-release run that standard depth-metric benchmarks pass clean; (2) false "looks fine" rate (cases a human reviewer would approve from the depth map alone but the harness flags) before vs. after adoption; (3) for a team that adopts the CI gate, ordering-regression catch rate on subsequent model/quantization swaps.

## Why Now
Qualcomm AI Hub Models and similar edge model hubs have made deploying quantized depth models to NPU hardware routine over the last year, but the validation tooling that ships alongside them hasn't kept pace with the specific failure modes NPU quantization introduces (the proposing issue frames this explicitly as a quantization-adjacent concern). The request surfaced this month against an actively maintained official repo, meaning there's a live, receptive integration point right now rather than a cold outreach to an unmaintained project.

## MVP Sketch
Scope: 30-50 hand-captured scene pairs across 4-5 failure categories (occlusion, thin objects, reflective surfaces, low light, texture-poor), ground-truthed with a consumer depth camera (e.g., iPhone LiDAR) for genuine near/far certainty, not estimated. Stack: Python harness wrapping ONNX Runtime + TFLite, a simple ordering-violation scorer, a Markdown/HTML report generator. Single experiment that validates or kills it: run the harness against 3-4 publicly available depth models (Depth Anything V2 at a couple of quantization levels, MiDaS) and confirm it actually catches at least one real ordering inversion that the models' published accuracy benchmarks don't flag — if it can't find any real inversions in a reasonably-sized corpus, the hypothesis that this is a common silent failure (not just a theoretical one) is wrong and the idea should be shelved.

## Risks & Open Questions
- The failure mode might be rare enough in practice (vs. theoretically possible) that a 30-50 scene corpus never catches a real case — the MVP experiment above is designed to test this directly before further investment.
- Ground-truthing "unambiguous near/far" at the needed precision requires real depth-sensing hardware per scene, which limits how fast the corpus can grow community-style compared to a purely synthetic/simulated corpus.
- Qualcomm or another hub vendor could ship this themselves once the issue gets attention — the author's own framing ("I'd like to contribute") suggests this might land inside `ai-hub-models` directly, which would undercut a standalone tool's differentiation unless this project explicitly targets being model/vendor-agnostic (works for non-Qualcomm edge targets too) from day one.
- No existing stereo/LiDAR-ground-truthed public corpus for this exact purpose was found in the gap-analyst's search — building one from scratch, even small, is real upfront work before the harness has anything to run against.
