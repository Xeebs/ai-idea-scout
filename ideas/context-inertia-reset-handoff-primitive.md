## The Gap
Drew Breunig's HN front-page essay "The State of Context Engineering" (275pts, 67cmt, 2026-10-25) names "context inertia": long-running agents plateau or fixate on a dead-end hypothesis *even with huge context windows* — the problem isn't information loss, it's reasoning momentum. The proposed fix is a periodic, deliberate reset that hands off state via an explicit memo instead of letting the agent silently self-compact. Every cited mention is conceptual; two live open Claude Code feature-request issues ask for exactly this capability, confirming unmet, active demand rather than an already-shipped harness feature.

## The Project
A harness-level primitive that watches a running long-horizon agent session for plateau signals — repeated near-identical tool-call sequences, N consecutive turns with no net test/diff progress, or an explicit stuck-loop marker — and, on trigger, pauses the session and asks the agent to author a structured memo (restated goal, hard constraints, every already-tried approach with why it failed, current best hypothesis). The session is then hard-reset: a fresh context seeded only with that memo, not the stale transcript. The deliberate discard-and-reseed is the centerpiece, not a feature bolted onto compaction — it's betting that fixation survives information preservation and needs an active intervention instead.

Components: a plateau-detection heuristic module (pluggable signals: diff/test-progress flatline, tool-call-sequence repetition, elapsed-turns-since-last-improvement); a fixed memo template and a forced "write your reset memo" prompt; a session reseed step that discards the prior transcript entirely; a log of every reset event (trigger reason, memo content, whether the new session converged faster) for later tuning of the detector.

## Tangible Impact
**Population**: Developers running autonomous or semi-autonomous coding-agent sessions on multi-hour or multi-day tasks — large refactors, flaky/hard-to-reproduce bug hunts, exploratory debugging and research loops — a subset of the hundreds-of-thousands-scale Claude Code/Codex/Cursor user base reported in 2026 vendor disclosures, specifically those whose tasks are open-ended enough to risk hypothesis fixation rather than a quick single-file edit.
**Mechanism**: Today, a fixated agent either burns tokens and wall-clock time repeating the same failed approach until a human notices and manually kills the session, or an automatic lossy compaction event fires and carries the same stale framing forward since it summarizes the existing fixation rather than breaking it. A deliberate, triggered reset-with-memo converts "someone eventually notices and intervenes" into an automatic, logged event, and strips the stale reasoning momentum on purpose while keeping only the facts (goal, constraints, what's been tried) that matter.
**Measure**: (1) Turns/tokens spent re-attempting the same dead-end approach before escaping, with vs. without the reset trigger, on a reproduced "stuck agent" scenario set. (2) Task completion rate and wall-clock time on long-horizon tasks, reset-primitive vs. standard-compaction vs. no-intervention baselines. (3) Rate of human-initiated manual session kills (a proxy for the detector missing or over-firing), before vs. after adoption.

## Why Now
The last 30 days produced the clearest naming yet of this failure mode (dbreunig's 275pt/67cmt essay) plus two live, open Claude Code feature-request issues asking for a self-checkpoint-and-reset primitive — real, current, unmet demand — and 2026's agentic coding tools now routinely support multi-hour/multi-day unattended sessions long enough for fixation to actually bite in practice rather than stay a theoretical edge case.

## Skill Angle
Given the pasted tail of a session transcript where the agent looks stuck (repeating a failed fix, re-trying something already discarded, or circling), produce a structured reset memo: restated goal, hard constraints, each already-tried approach with why it failed, and the most promising untried direction — meant to be pasted into a fresh session to resume cleanly. This differs from the project: the project is the always-on runtime that detects plateau automatically and performs the reset; the skill is a manual, one-shot diagnostic a person runs the moment they themselves suspect (not yet confirmed by an automated detector) their agent is stuck, with no infrastructure required.

## MVP Sketch
A thin wrapper around an existing CLI agent's session/hook API (Claude Code first) that: (1) tracks one simple plateau heuristic — e.g., K consecutive turns with no net test-pass or diff-size improvement — (2) on trigger, pauses and forces the agent to write a memo against a fixed template, (3) starts a new session seeded only with that memo, and (4) logs whether the new session converges faster than the old one did. Experiment: reproduce a handful of real "agent got stuck" scenarios (e.g., a flaky-bug hunt where the agent keeps re-trying the same failed patch) with and without the reset trigger, and compare turns-to-resolution. 2–3 weeks, 1–2 people, no new model training needed.

## Risks & Open Questions
- The plateau-detection heuristic is the hardest and least precedented part: too trigger-happy and it resets genuinely slow-but-productive work; too conservative and it never fires before a human already noticed and intervened manually.
- Overlaps conceptually with this repo's "Pin It" (`compaction-invariant-pinning-library.md`), which fixes a related but opposite-mechanism symptom — preserving already-tried-approach info through compaction rather than deliberately discarding context — and with "Ledger" (`lossless-context-state-manager.md`), which keeps everything versioned rather than pruning. This project's bet is that fixation survives even full information preservation and needs an active reset instead — an unproven claim from one essay, not yet empirically validated anywhere, and the strongest reason this might not work as designed.
- Having the agent author its own "reset memo" risks the memo inheriting the same flawed framing that caused the fixation in the first place, since the agent may not recognize it's stuck.
- No shipped harness natively exposes a clean "pause, demand a memo, hard-reset-and-reseed" primitive today; the first version will necessarily be narrower than "works everywhere," built against one CLI agent's hook API before any others.
