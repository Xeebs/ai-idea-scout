# Inherited Rules: A Constraint-and-Identity Transfer Layer for Agent-to-Agent Handoffs

- **Status**: PROPOSED
- **Date**: 2026-11-17
- **Topic**: Multi-agent architectures
- **Source**: research/2026-11-17-multi-agent-architectures.md · P7
- **Maturity verdict**: OPEN — WebSearch for "constraint transfer"/"identity transfer" at agent handoffs found only blog/practitioner discussion (aiweekly.co's summary of the originating r/AI_Agents post, tianpan.co, urandom.io, futureagi.com's glossary entry, channel.tel) naming the failure mode and recommending ad hoc "handoff contracts," but no named product, library, or paper implementing constraint/identity transfer as a first-class mechanism; no GitHub repo surfaced for this specific framing.
- **Format**: BOTH — the extraction-and-injection middleware is PROJECT-shaped (must read agent definitions and enforce at runtime), but drafting a constraint capsule for one described pipeline is a separable one-shot task.
- **Data Sources**: CONNECTED — reads the upstream and downstream agents' own definition files directly from the orchestration framework's agent manifest (e.g. Claude Code subagent `.md` frontmatter, a CrewAI agent YAML `backstory`/`role`/`goal` block, a LangGraph node's system-prompt string) to extract declared tone, forbidden actions, and business-rule limits, instead of asking a human to re-type them. No mature standard connector for "constraint extraction across frameworks" exists yet — this would be the first, built against one framework's manifest format initially (Claude Code subagents, since that's the dev environment this pipeline already runs in) with later adapters per framework. A MANUAL fallback (paste both agents' system prompts) is the day-one MVP path while the first connector is built.

## The Gap
A widely-summarized r/AI_Agents post (via aiweekly.co's "Multi-agent AI breaks on constraint transfer, not storage" writeup) argues the community keeps shipping shared-memory and context-handoff tools that solve the wrong failure: production multi-agent systems break "not because agents forget information, but because they forget their rules" — a persona, a compliance phrase, a discount ceiling, a scope boundary — the moment a task crosses from one agent to the next. Practitioners describe patching this with ad hoc "handoff contracts" in prose, and no named tool treats constraints/identity as a structured, carried-forward artifact the way context-engineering tools already treat conversational data.

## The Project
A constraint capsule that travels with every handoff, separate from (and complementary to) whatever data/context schema a pipeline already uses: at build time, an extractor reads the upstream agent's definition and pulls out its declared persona/tone, forbidden actions, numeric/business-rule limits, and compliance phrasing into a typed capsule; at handoff time, a runtime hook injects the relevant subset of that capsule into the receiving agent's system prompt or tool-call guardrails; after the receiving agent responds, a lightweight conformance checker flags responses that plausibly violate an inherited constraint (wrong tone, a stated limit exceeded, a forbidden topic touched) for review. The capsule, not the transport, is the centerpiece — this is deliberately narrower than a general handoff-context schema: it only carries *rules*, never task data, so it stays small enough to inject on every hop without context bloat.

Components: a constraint-extraction parser (starts with Claude Code subagent frontmatter, the format this pipeline's own subagents already use); a capsule schema (persona, forbidden-actions list, numeric limits, required phrasing); a runtime injector hook for one framework first; a post-hoc conformance checker comparing a receiving agent's actual output against the capsule it inherited.

## Tangible Impact
**Population**: Engineering teams running specialized multi-agent pipelines where a general-purpose triage/orchestrator agent hands a task to a narrower specialist agent — e.g. a support-triage bot escalating to a billing or refunds agent, a sales-qualification agent handing to a pricing agent — the same shape of team the digest's P2/P5/P6 evidence (trust layers, vendor relays, shared-memory bugs) all come from, but specifically the subset hitting *rule* violations after a correctly-delivered data handoff, which is exactly the failure the aiweekly.co post distinguishes from a memory/data bug.
**Mechanism**: Today a receiving agent gets the conversation and task data but re-derives its own defaults for tone, limits, and scope from its own system prompt alone — any constraint the upstream agent was quietly enforcing (e.g. "never promise a refund over $50 without approval") has to be manually re-declared on every specialist agent or it silently lapses the moment a handoff happens. A constraint capsule makes that inheritance explicit and checkable instead of something each new specialist agent has to remember to copy-paste.
**Measure**: (1) Rate of constraint-violation incidents per 100 handoffs (a receiving agent's output breaking a rule the upstream agent enforced) on a pilot pipeline, before vs. after adoption. (2) Percentage of handoffs where the post-hoc conformance checker flags zero violations on a labeled test set of known-bad historical transcripts (recall on cases a human would also flag). (3) Time for an engineer adding a new specialist agent to a pipeline to correctly re-declare an existing constraint, with the capsule auto-injected vs. manually re-authoring it.

## Why Now
Multi-agent pipelines with specialist handoffs moved from demo to production this year (the same shift the digest's P5/P6 evidence documents), and the community's own framing — "we keep building memory tools for the wrong problem" — is itself less than 30 days old, meaning this specific diagnosis of the failure mode (constraints, not data) is newly named rather than newly possible; the underlying extraction task (reading a structured agent-definition file and pulling out declared rules) is a solved LLM capability today, no model-capability wait required.

## Skill Angle
Given an upstream agent's definition (system prompt, subagent frontmatter, or a prose description of its rules) and a downstream agent's definition, draft a constraint capsule: the persona/tone to carry over, the forbidden actions, the numeric/business-rule limits, and any required phrasing — plus a flagged list of ambiguous rules the descriptions didn't make explicit (e.g. "upstream caps discounts at $50 but doesn't say whether that's per-item or per-order"). This is useful immediately for anyone describing their pipeline, independent of whether the runtime injector or conformance checker is ever adopted.

## MVP Sketch
A Python parser that extracts a constraint capsule from Claude Code subagent `.md` frontmatter + system-prompt body, a capsule schema (JSON), and a conformance checker that scores a set of 10 real-shaped transcripts (half intentionally rule-violating) for recall/precision against the capsule. Experiment: hand-construct 10 upstream→downstream handoff transcripts where half silently violate an upstream rule; if the conformance checker can't catch the clear violations at a usable precision/recall, the capsule's value claim fails before any runtime injection work is justified. 2–3 weeks for 1–2 people.

## Risks & Open Questions
- The evidence for this pattern is thin — a single aggregator's summary of one Reddit post, with no named repo, no engagement numbers beyond the aggregator's own framing, and no second independent thread found; this is weaker-sourced than most ideas in this index and could be one commenter's framing rather than a widespread pain.
- Overlaps conceptually with "Handoff Envelope" (data/decision schema) and "Scope Trace" (authorization/privilege) already in this index — this idea is deliberately scoped to *business-rule/persona/tone* constraints only, the slice neither covers, but a reviewer should confirm that distinction holds once real pipelines are examined rather than just argued from the digest's framing.
- Constraint extraction from a free-text system prompt is itself an LLM task that can mis-extract or hallucinate a rule that was never actually declared — the extractor needs its own eval before being trusted.
- A framework or vendor (OpenAI Agents SDK, LangGraph) could fold "carry declared guardrails across handoffs" into their own handoff primitive before an independent build gains traction, similar to the risk already noted on Handoff Envelope.
- Enforcement via conformance checking is probabilistic, not a hard guarantee — this reduces silent constraint drift but cannot replace a hard-coded guardrail for anything safety-critical.
