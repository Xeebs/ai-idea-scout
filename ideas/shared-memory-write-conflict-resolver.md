## The Gap
GreenNode's shared-memory design guide proposes a "scope-chain" architecture — a privileged-write global layer of facts plus per-agent namespaced working state — as the fix for flat shared memory causing cross-agent context pollution. But VentureBeat's coverage of Tencent's Team Memory states plainly there's no documented mechanism for resolving conflicting writes between agents ("whose memory wins"), and Mem0's own Organizational Memory beta page markets a governance layer without explaining how write conflicts get resolved. Both are shipped or beta'd products, both acknowledged-incomplete on exactly this governance question — it's a real, open gap at the top of an otherwise-real architecture pattern.

## The Project
A conflict-resolution middleware sitting in front of the global, privileged-write layer of a scope-chain memory architecture. When two agents attempt to write facts that contradict each other or an existing entry for the same key/entity, the layer doesn't silently overwrite or block outright — it runs a structured resolution protocol: a confidence-weighted comparison (source provenance, recency, agent-reported certainty), and either an automatic resolution when confidence is clearly decisive, or a "contested fact" state that preserves both versions with provenance until a designated arbiter agent or human resolves it. Every resolution, automatic or escalated, is written to an audit trail answering "what did the system believe, when, and why did it change." The resolution protocol is the centerpiece — this is deliberately narrower than a general memory store or an access-control layer; it only exists to answer the one question neither shipped product currently answers.

Components: a conflict detector (compares an incoming write against existing global-layer entries for the same key/entity, using embedding similarity plus a cheap-model contradiction check); a resolution-policy engine (auto-resolve / escalate-to-arbiter / human-review, configurable per fact category); a contested-fact store retaining both versions with provenance pending resolution; an audit log of every resolution decision.

## Tangible Impact
**Population**: Teams running production multi-agent systems where 5+ specialized agents (e.g., sales-ops, support, and research agents) draw on one shared global fact layer — the same population Tencent's Team Memory and Mem0's Organizational Memory beta are actively selling to, who today have no way to detect or resolve a write-write conflict between two of their own agents.
**Mechanism**: Without this, a contradiction either silently overwrites a possibly-correct earlier fact, or both versions coexist undetected in the store — so whichever agent happens to read the entry next acts on an arbitrary, non-deterministic version of "the truth," and the resulting inconsistent decisions are traceable today only through manual log archaeology after something has already gone wrong downstream. The resolution layer converts a silent, undetectable failure into a visible, policy-governed, auditable event resolved before it propagates to the next agent that reads the fact.
**Measure**: (1) Conflict-catch rate — detected write-write conflicts versus a baseline of silent overwrites, on a synthetic write-contention benchmark seeded with deliberately contradictory facts. (2) Time to resolution (auto-resolved vs. escalated-to-human cases), versus today's baseline of "discovered only after a wrong downstream decision is traced back." (3) Downstream decision-consistency rate — the fraction of agents reading the same contested fact that act on the same, resolved version — before vs. after adoption.

## Why Now
Two funded vendors (Tencent, Mem0) shipped or beta'd shared agent-memory products in 2026, and independent coverage (VentureBeat, Mem0's own docs) names conflict resolution as the explicit missing piece in both — demand for shared memory is now proven in the market, and the one specific mechanism nobody has shipped is newly visible precisely because the surrounding infrastructure just became real enough to expose it.

## Skill Angle
A "Memory Conflict Policy Draft" skill: given a description of an organization's shared-memory setup (what agents write to the global layer, what kinds of facts they write, how often writes have historically conflicted or been corrected), draft a resolution policy — which fact categories should auto-resolve by recency vs. confidence, which should always escalate to a human, and what provenance metadata needs to be captured to make that call. Useful today as a planning exercise before any team builds or adopts the enforcement middleware itself.

## MVP Sketch
3–4 weeks, 1–2 people: wrap a Postgres-based global fact table with a write-intercept proxy; implement embedding-similarity-plus-key-match conflict detection and a simple confidence-weighted auto-resolve policy with a review-queue fallback. Experiment: simulate 3 agents writing to the shared table with injected contradictory facts, and measure the conflict-catch rate and resolution time against an unprotected baseline where contradictions simply overwrite silently.

## Risks & Open Questions
- Mem0 or Tencent could ship exactly this as a governance feature on their own existing products — the most direct competitive risk, since both already named the gap publicly.
- Confidence-weighted auto-resolution is itself a judgment call that can be wrong in either direction; miscalibration could quietly bury a correct fact as often as it catches a bad one.
- At real production write volume, a centralized conflict arbiter may need to become a proper CRDT-style conflict-free data structure instead of a synchronous intercept-and-decide proxy — a materially different architecture if the MVP's simple approach doesn't scale.
- This idea must stay clearly differentiated from the repo's existing Write Gate (single-agent long-session poisoning screening) and Reconcile (ephemeral sub-agent task-return merging) — both share mechanism DNA (contradiction detection) but target different populations and failure points; conflating them would dilute all three.
