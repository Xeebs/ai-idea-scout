# Prune Once: A Model-Judged, Pay-Once Context Pruning Layer for Noisy Agent Tool Output

- **Status**: PROPOSED
- **Date**: 2026-11-20
- **Topic**: Agentic AI & autonomous agents
- **Source**: research/2026-11-20-agentic-ai-autonomous-agents.md · P3
- **Maturity verdict**: PARTIAL — Filed as an open, unimplemented feature request against Google's actively-maintained Antigravity CLI (`google-antigravity/antigravity-cli#1429`). Adjacent but non-matching prior art exists: `pi-context-prune`'s "agentic-auto" mode lets the LLM itself decide what to prune (closest match), while Elixir's `Condukt.Compactor.ToolResultPrune` and a Hermes `context_compressor.py` do deterministic, non-model placeholder replacement — and Atlassian's Rovo Dev blog explicitly argues *against* model-judged compaction in favor of structure-aware rules. No generic, widely-adopted tool doing exactly "model swaps junk output for a one-line summary once" was found.
- **Format**: BOTH — the live interception/replacement layer must sit inside a running agent's context-assembly step every turn (persistent middleware); manually reviewing a captured trace and drafting the one-line replacement for a specific junk tool output is a separable one-shot judgment task.
- **Data Sources**: BOTH apply differently by half — the **project** is CONNECTED: it wraps the agent framework/CLI's own tool-call execution and context-window-assembly step (a stable extension point in the Claude Agent SDK, LangGraph, and comparable CLIs like Antigravity) to intercept each turn's raw tool output before it re-enters context on later turns. No new external data source is read; the hook point already exists maturely, but no connector performing model-judged pay-once pruning on it exists today. The **skill** is MANUAL: the user pastes one noisy tool-call output (e.g. a long shell/log/search-result dump) plus the 1-2 surrounding conversation turns that establish what the agent actually needed from it.

## The Gap
A same-week GitHub feature request against Google's Antigravity CLI ("[Feature Request]: Let the model replace a junk tool output with a one-line summary (model-judged context pruning)," 2026-11-05, 2 reactions/2 comments) names a specific, recurring cost: when a tool call returns output the agent didn't need, every subsequent turn re-reads the full junk payload instead of paying the summarization cost once. Existing context-compaction tools either compress everything deterministically (rule-based placeholders) or compress the whole conversation periodically — none let the model itself flag *this one specific tool result* as junk and permanently swap it for a one-line summary the moment it's recognized as unneeded, which is the exact mechanism requested and still open against a real, maintained CLI.

## The Project
A middleware layer that sits between an agent's tool-call return and the context it carries forward. After each tool call completes and the agent's next reasoning step runs, the layer asks the model a cheap, structured question — "was this tool output's full content actually used, or can it be replaced by a one-line summary from here on?" — and if the answer is junk, permanently rewrites that turn's content in the stored context to the one-line summary before the next turn starts. The cost is paid once, at the moment the model judges the output unneeded, instead of being re-paid (in tokens, latency, and attention dilution) on every later turn that re-reads the full payload. Unlike deterministic placeholder tools, the judgment of "was this needed" is made by the same model doing the task, using its actual usage of the content as the signal — not a fixed rule (truncate after N lines, strip by content-type).

Components: a tool-output interception hook for one framework first (Claude Agent SDK or a raw CLI loop like Antigravity's); a lightweight post-turn "was this needed" classifier call; an in-place context rewrite/pin mechanism that replaces the original turn's stored content; a dropped-content log so a human can audit what got pruned and why.

## Tangible Impact
**Population**: Developers running long-horizon agentic CLI sessions (Claude Code, Codex CLI, Antigravity, and comparable tools) on tasks that make many tool calls with noisy outputs — web search results, build/log dumps, large file reads, API responses — where context bloat from repeatedly re-paying attention to already-irrelevant output drives up both token cost and degrades focus on the evidence that actually matters. GitHub reported Copilot passing 1.8 million paid subscribers by 2024, and agentic CLI adoption has grown substantially since; the directly affected subset — developers running multi-tool-call loops long enough to accumulate real junk-output bloat — is plausibly in the hundreds of thousands.
**Mechanism**: Today a long agent session either keeps paying to re-read a junk tool output on every subsequent turn (cost and dilution compound with session length) or relies on a periodic, lossy, whole-conversation compaction pass that can't selectively target just the junk. A pay-once, model-judged swap removes exactly the content the model itself has already signaled it doesn't need, the moment it's recognized, without touching content still in use — shrinking the token bill and the noise-to-signal ratio for everything after that point in the session.
**Measure**: (1) Token consumption on a held-out suite of long multi-tool-call agentic tasks, with vs. without the layer, at matched task-success rate. (2) Rate of false prunes — content later needed but already swapped for a summary, recovered via the dropped-content log — kept below a defined tolerance. (3) Session length (number of turns) before context-window pressure forces a full compaction event, extended versus baseline.

## Why Now
The underlying need was named this week against a real, actively-maintained CLI (Antigravity) rather than a toy or abandoned project, and the closest prior art (`pi-context-prune`'s agentic-auto mode) proves the core mechanism — letting the model itself decide what to prune — is technically workable today with no new model capability required; what's missing is a framework-integrated, pay-once implementation rather than a periodic whole-conversation pass.

## Skill Angle
Given one pasted tool-call output (e.g. a long log dump or search result) plus the surrounding 1-2 turns showing what the agent actually extracted from it, judge whether the full output is still needed going forward, and if not, draft the one-line summary that should permanently replace it — the identical judgment call the runtime layer would make programmatically, done once by hand. Useful today for anyone manually trimming a bloated session transcript before a context-window limit hits, or for designing the classifier's prompt before the middleware exists.

## MVP Sketch
2–3 weeks, 1–2 people: build the interception hook for one agent loop (a raw Claude Agent SDK loop or an open-source CLI with an accessible tool-call lifecycle), wire in the post-turn "was this needed" classifier call, and implement the in-place context rewrite. Experiment: run a held-out set of 15-20 long, multi-tool-call synthetic tasks (web-research-and-summarize, log-triage-and-fix) with and without the layer, measuring token count and task success; if task success drops materially versus the token savings gained, the pruning is too aggressive and the approach should be killed or tuned before further investment.

## Risks & Open Questions
- Atlassian's own Rovo Dev team explicitly argues against model-judged compaction in favor of structure-aware deterministic rules — this project bets against that stated position and must demonstrate the model-judged approach doesn't regress accuracy to justify existing.
- A mainstream agent framework (LangChain, the Claude Agent SDK itself) could ship an equivalent built-in feature quickly once named, as has happened to several comparable context-engineering patterns in this project's own backlog.
- The classifier call itself costs tokens and latency every turn a tool returns content — the net savings claim depends on that overhead staying smaller than the re-read cost it prevents, which must be measured, not assumed.
- False prunes (swapping out content that turns out to be needed several turns later) are the core failure mode; the dropped-content log is a mitigation, not a fix, and recovery still requires the agent (or a human) to notice something is missing.
